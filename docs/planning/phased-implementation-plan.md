## 总目标

在不复制旧 AstraMind 机构级复杂度的前提下，尽快跑通个股实盘：

```text
文档与 UI 示意图批准
  → 本地开发底座
  → 点时正确的历史数据 + MiniQMT 多时标行情/收盘封存
  → 日频粗筛 + 候选级按需日内验证
  → 多策略短线证据
  → 多候选 Research Shadow
  → 明确授权的 MiniQMT Paper
  → 有限真实执行
```

因子长线组合、大盘/行业看板、资金相对轮动和 ETF 轮动复用同一数据、组合、风险与执行契约，不建立平行系统。

## 实施原则

- 阶段是能力边界，不是强制等待时长。
- 只有 UI 视觉批准以及资金/券商受保护决策需要打断用户。
- 已批准工作包内的例行实施不反复审批。
- 每个独立能力都有有限需求和工作包。
- 每个重要界面先出版本化示意图，再写代码。
- 一个功能被阻断时，不阻塞无关研究和文档。
- 后续阶段只能通过版本化公共契约复用前序证据。
- 面向用户的文档使用中文；Agent/Vibe 内部规范按 `AGENTS.md` 允许保留英文。

- 行业内排序展示事件/情绪、技术/量价、基本面、风险、反转和覆盖率；
- 排序只形成研究优先级，不直接形成组合目标或订单。

复用候选：

- 连续位置与趋势评分；
- 行业广度和覆盖；
- 生命周期分类；
- 状态持续和迁移；
- ETF 确认；
- 注册表/Fixture 与一致性测试。

不迁移：

- 旧发布门禁；
- 固定 60 日观察；
- 手工 JobRun；
- Preview/Formal 状态机；
- 旧页面。

当前注册表为 SW2021 L1，实际行业数来自数据快照；引擎与界面必须与数量无关，不迁移
旧系统的 56 行业或 22 个 ETF 方向注册表。

日线最新日期和 MiniQMT 实时新鲜度。**

- 版本化 ETF 池和行业映射；
- 生命周期、相对强弱、广度和流动性假设；
- 首案为周度主调仓，日度只做风险/可交易性检查；
- 跟踪、价差/代理、成交额、规模、重叠和成本；
