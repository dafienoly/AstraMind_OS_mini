# 分阶段实施计划

- 计划版本：1.7.0
- 初始日期：2026-07-26
- 更新日期：2026-07-27
- 状态：阶段 0 仍待部分 UI 批准；阶段 1C、2C、3A/3B/3C/3E 与 4B 本地基线已建立

## 总目标

在不复制旧 AstraMind 机构级复杂度的前提下，尽快跑通个股实盘：

```text
文档与 UI 示意图批准
  → 本地开发底座
  → 点时正确的历史数据 + MiniQMT 实时行情
  → 多策略短线证据
  → 本地 Shadow
  → 明确授权 MiniQMT
  → 有限真实执行
```

因子长线组合、大盘/行业看板、资金相对轮动和 ETF 轮动复用同一数据、组合、风险与执行契约，不建立平行系统。

## 实施原则

- 阶段是能力边界，不是强制等待时长。
- 只有 UI 视觉批准以及资金/券商受保护决策需要打断用户。
- 已批准工作包内的例行实施不反复审批。
- 每个独立能力都有有限需求和工作包。
- 每个重要界面先出版本化示意图，再写代码。
- 一个功能被阻断时，不阻塞无关研究和文档。
- 后续阶段只能通过版本化公共契约复用前序证据。
- 面向用户的文档使用中文；Agent/Vibe 内部规范按 `AGENTS.md` 允许保留英文。

## 路线总览

| 阶段 | 结果 | 需要用户决定 |
| --- | --- | --- |
| 0 | 仓库、中文文档、上下文、路线图、17 个工作面的完整 UI 提案 | 批准/修改各个待审 UI 提案准确版本 |
| 1 | 快速本地开发循环、契约骨架、界面框架与 UI Lab | 仅在示意图修改时确认 |
| 2 | 可重建的历史快照、MiniQMT L1 实时流与提供方能力矩阵 | 首次 RPC 调用范围和权限缺失处置 |
| 3 | 多类短线个股策略和封存回放 | 证据完成后手动晋级候选 |
| 4 | 本地 Shadow、MiniQMT 账户/交易适配器、Paper 与有限 Live | 账户读取、Paper、授权范围、Live、首单 |
| 5 | 因子挖掘、分行业模型、周度长线组合 | 晋级长线策略版本 |
| 6 | 大盘/行业/资金轮动、生命周期与 ETF 轮动 | 批准各 UI 提案及后续 ETF 晋级 |
| 7 | 恢复、监控、性能和日常运行纪律 | 重大风险或资金变更 |

### 数据质量证据

- 相同输入重复抓取/构建产生相同哈希；
- 晚公告财务/股东记录不能进入更早快照；

- 退市、ST、停牌和封板示例行为正确；
- 缺页不能发布完整快照；
- 覆盖报告暴露日期、证券、行业和数据集缺口；
- 行业注册表数量来自版本，不写死 56。
- MiniQMT L1 断线、重连和重复消息不产生静默缺口或重复观察；
- L2 无权限时明确失败关闭；
- Tushare 与 MiniQMT 来源冲突时输出差异和版本化选源结论。

### 退出条件

一个命名 `DataSnapshot` 可以重建所有短线研究输入并提供行业面板；MiniQMT L1
实时流具有独立会话、可见新鲜度和不可变微批，能够安全支持当前观察与后续 Shadow。

## 阶段 3：短线个股 MVP

### 目标

公平比较多种短周期假设，为 5 万元短线分仓生成可信目标。

### 3A：点时正确股票池

**状态：WP-0004 已完成首个可执行基线。**

从当时真实存在的全部 A 股开始，应用明确的资格和容量检查。

不把“20 日成交额前 800–1500 只”冻结为产品规则，而是研究：

- 最短上市时间；
- ST、停牌和涨跌停；
- 20 日成交额中位数与换手；
- 订单金额/近期成交额；
- 股价与 100 股整数手可行性；
- 最近数据覆盖；
- 宽流动性研究通道；
- 事件覆盖通道：在订单仍可执行时，保留下游排名较低但出现龙虎榜等事件的股票。

这样避免把计算捷径变成不可解释的遗漏规则。

### 3B：统一回测引擎

**状态：WP-0004 已完成首个可执行基线。**

- 点时快照与历史股票池；
- T+1、涨跌停、停牌、整数手、费用、滑点和流动性；
- 信号时间、计划执行时间、实际成交、拒绝和退出原因；
- 策略无关指标和逐笔台账；
- 滚动开发与不可见封存回放。

### 3C：并行策略家族

**状态：WP-0005 已完成三类候选与统一回测接入；尚无封存期晋级证据。**

首批假设：

- 事件/关注：龙虎榜、异常量额、涨跌停与参与结构；
- 动量/突破：价格量能趋势、强度和拥挤控制；
- 反转/量价：衰竭、假突破、波动与流动性。

股东户数和行业状态是慢速上下文，不强制成为入场触发器。每个家族支持 2/5/10 个交易日周期并产生不可变 `StrategyVersion`。

### 3D：策略竞技场

- 以已批准的 UI-PROP-0004 v0.2 作为短线比较、候选个股价格核验与晋级视觉基线；
- 展示共同快照、成本、区间、收益、回撤、换手、胜率、盈亏比、容量、稳定性和失败场景；
- 明确区分开发、封存回放和当前 Shadow。

### 3E：短线目标组合

**状态：WP-0006 已完成 5 万元、最多两只与现金有效的本地目标基线。**

- 常态持有 1–2 只；
- 现金是合法目标；
- 应用单股、行业、流动性、跳空和回撤限制；
- 只产生 `PortfolioTarget`，不直接生成券商订单。

### 评价区间

- 开发/调参：截至 2022 年，并受各数据集实际起点约束；
- 封存回放：2023-01-01 至 2025-12-31；
- 当前观察：具备运行数据后使用 2026 本地 Shadow。

龙虎榜策略不能声称拥有早于已核验龙虎榜历史的证据。

### 评价指标

- 区间适用的 CAGR/绝对收益；
- 最大回撤与回撤时长；
- Sharpe、Sortino、Calmar；
- 胜率、盈亏比和尾部损失；
- 换手、交易数量和持仓时间；
- 滑点/成本敏感度；
- 分年份、市场状态、行业组和周期表现；
- 容量与成交/拒绝率；
- 参数和股票池稳定性。

不能用单一收益指标决定晋级。

### 退出条件

至少一个候选具备可重复的开发与封存证据，用户能检查逐笔台账和失败场景，并可手动晋级短线冠军，但不会因此启用券商。

## 阶段 4：本地 Shadow 与 MiniQMT 执行路径

### 目标

先完整跑通本地订单生命周期，再在不改变策略/组合语义的前提下增加券商适配器。

### 4A：订单计划与常设授权

- 将目标组合和当前持仓转为不可变 `OrderPlan`；
- 建模现金、整数手、T+1 库存、限价、交易窗口和撤单；
- 定义常设授权字段与异常原因；
- 用独立需求冻结 8%/10%/12% 回撤动作。

### 4B：本地 Shadow

**状态：WP-0006 已完成确定性成交与 SQLite/WAL 事件账本基线；持续运行与完整对账待后续。**

- 使用行情/Bar 的确定性成交政策；
- 支持部分成交、拒绝、停牌、封板、陈旧行情和断开；
- 重启恢复与幂等提交；
- 持仓、现金、盈亏和对账投影；
- 日度复盘和策略归因。

不设置固定观察时长。手动晋级使用可见封存证据与已有 Shadow 诊断。

### 4C：今日、组合与异常收件箱

以 UI-PROP-0003、0006、0007 和 0008 的已批准版本作为视觉基线。

- 今日显示计划与不行动原因；
- 组合显示实际/目标和风险；
- 异常收件箱只处理超授权或异常；
- 刷新从服务端恢复状态。

### 4D：MiniQMT 只读账户与启动对账

用户已确认本机 MiniQMT 能读取实盘/模拟盘账户，但本仓库首次调用仍使用单独只读
工作包和明确授权：

- 记录 RPC/客户端版本、账户模式、查询能力、回调和权限，不记录真实账户标识；
- 适配 `query_stock_asset`、`query_stock_positions`、`query_stock_orders` 和
  `query_stock_trades`；
- 形成带 `as_of` 的账户快照，明确区分模拟盘与实盘；
- 每次启动读取资金、持仓、未完成委托和当日成交并完成对账；
- 差异、断线或陈旧状态阻断新订单。

### 4E：MiniQMT 模拟盘 Paper

- 使用隔离交易端口适配 `order_stock`、`cancel_order_stock` 的同步/异步接口；
- 将委托、成交、资产和持仓回调映射到不可变 `ExecutionEvent`；
- 处理幂等、重复、乱序、迟到、断线重连和撤单竞争；
- 先在模拟盘验证同一 `OrderPlan`，不因 Paper 通过自动进入 Live；
- 禁止网关导入策略、模型或优化器。

### 4F：有限 Live

- 在独立 Live 与首单授权后复用已经通过 Shadow/Paper 的交易端口；
- 启动对账、常设授权、风险、急停和新鲜行情任一失败时阻断；
- 第一阶段只支持授权范围内的 A 股股票委托与撤单；
- 信用、约券、期货和期权保持范围外。

### 受保护检查点

分别明确批准：

1. 本仓库首次调用 MiniQMT 行情 RPC；
2. 读取真实 MiniQMT 账户状态；
3. 模拟盘 Paper 下单；
4. 第一份常设授权及限制；
5. Paper → Live；
6. 第一笔真实订单。

这些批准不意味着授权范围内仍需逐笔审批。

### 退出条件

同一个订单计划能够经过 Shadow、MiniQMT 模拟盘和经授权的 Live 适配器，并具有
确定、可恢复的状态。全部受保护检查点完成前，Live 保持关闭。

## 阶段 5：因子挖掘与周度长线组合

### 目标

为 10 万元长线分仓形成按周评估、约 5 只股票、分行业建模的目标组合。

### 5A：因子目录与点时面板

- 价值、质量、盈利、成长、动量、反转、低波、流动性和事件/上下文；
- 公式、适用范围、缩尾、中性化、滞后、覆盖、换手与经济机制；
- 行业特定排除和定义；
- 因子相关、衰减、单调性、容量和稳定性。

只增加声明因子实际使用的财务字段。

### 5B：排序基线

- 简单复合与正则线性基线；
- 表格数据的梯度提升排序/回归；
- Purged/Embargoed 滚动评估；
- 20/60 个交易日预测；
- 校准与不确定性。

### 5C：分行业模型

- 科技；
- 周期，包括有色与能源；
- 传统经济，包括交通、酒和化工；
- 样本不足时的全市场回退模型。

比较全市场统一模型、分组专家和分层/多任务方案。样本或覆盖不够时，行业模型不能训练。

### 5D：PyTorch/ROCm 挑战者

- 在小 Fixture 上验证可重复性和 GPU/CPU 一致性；
- 从多任务/混合专家监督排序开始；
- 记录训练数据、随机种子、代码、环境和模型身份；
- 成本后与表格基线比较；
- 没有稳定样本外提升，不晋级复杂模型。

### 5E：优化器接口与基线

`OptimizationProblem` 包含预测、不确定性、当前持仓、现金、成本、流动性、风险暴露、上下限和分仓约束。

首个优化器优先稳健：

- 近等权或风险感知初始权重；
- 单股与行业限制；
- 流动性与整数手可行性；
- 换手/成本惩罚；
- 不确定性收缩；
- 允许现金。

后续可以加入层次风险平价、贝叶斯收缩、可微优化或受限 RL 分配，不改变公共契约。

### 5F：周度工作流

- 周五盘后或配置的周度评估；
- 清楚说明持有、调仓或不行动；
- 长线策略竞技场与晋级；
- 与短线分仓进行账户级统一对账。

### 退出条件

长线分仓具有可重复周度目标、稳定优化诊断、分行业证据，并通过同一执行路径进入本地 Shadow。

## 阶段 6：大盘、行业、资金轮动、生命周期与 ETF

### 目标

把市场和行业结构变成清楚的观察界面，并建设独立可检验的 ETF 轮动策略。

### 6A：大盘看板

- 可切换主要宽基指数的日/周/月蜡烛、成交量和均线；
- 指数方向与回撤；
- 广度、新高/新低和参与度；
- 涨跌停、炸板和连板；
- 成交额与流动性分位；
- 风格与大小盘；
- 波动与市场状态置信度；
- 陈旧、不完整和证据分歧状态。

应用壳层、行业热力和指数蜡烛图遵循已批准的 UI-PROP-0001 v0.3；v0.2 保留为历史批准基线。

### 6B：行业热力看板

- 版本化行业分类与归属覆盖；
- 收益、相对强弱、广度、成交额/换手、波动、估值和龙头；
- 科技/周期/传统经济比较视角；
- 右侧检查器和历史轨迹。

必须遵循已批准的 UI-PROP-0001。

### 6C：行业资金相对轮动

- 冻结首期申万行业注册表、基准和公式版本；
- 计算相对趋势、相对动量、四象限、迁移尾迹和结构跃迁；
- 使用一个 `DataSnapshot` 产生不可变 `MarketRotationSnapshot`；
- 提供搜索、筛选、选择、尾迹长度、播放、暂停、变速、拖动和回到最新；
- 日期变化时节点、详情、统计和事件保持同一 `as_of`；
- 浏览器只回放已加载有界数据，不逐帧请求；
- 失败时不显示演示点或前值；
- 始终只读并显示“研究观察，不是买卖信号”。

必须遵循 REQ-2026-0002 和已批准的 UI-PROP-0002。

### 6D：行业生命周期迁移

以已批准的 UI-PROP-0011 v0.1 作为结构地图和行业内研究排序的视觉基线：

- 用版本化的强势参与率 `S`、低位修复参与率 `L`、成交额占比气泡和置信度描边展示行业结构；
- 提供按生命周期分组的可读行业索引，重叠或覆盖不足不能导致行业消失；
- 地图、索引、行业研究排序和联动个股蜡烛图使用同一个 `as_of`、行业分类版本和数据快照；
- 行业内排序展示事件/情绪、技术/量价、基本面、风险、反转和覆盖率；
- 排序只形成研究优先级，不直接形成组合目标或订单。

复用候选：

- 连续位置与趋势评分；
- 行业广度和覆盖；
- 生命周期分类；
- 状态持续和迁移；
- ETF 确认；
- 注册表/Fixture 与一致性测试。

不迁移：

- 旧发布门禁；
- 固定 60 日观察；
- 手工 JobRun；
- Preview/Formal 状态机；
- 旧页面。

迁移注册表可以暂时包含 56 行业和 22 方向，但引擎与界面必须与数量无关。

### 6E：ETF 轮动研究

- 版本化 ETF 池和行业映射；
- 生命周期、相对强弱、广度和流动性假设；
- 首案为周度主调仓，日度只做风险/可交易性检查；
- 跟踪、价差/代理、成交额、规模、重叠和成本；
- 滚动与封存回放；
- 通过共享组合/执行路径进入本地 Shadow。

### 6F：ETF 界面

以已批准的 UI-PROP-0009 v0.2 作为视觉基线。解释候选方向、选择/拒绝原因、所选 ETF 蜡烛图、目标变化、成本和生命周期证据，不能把生命周期、资金轮动图或 ETF 蜡烛图直接变成订单按钮。

### 退出条件

大盘和行业看板真实可用；指数、行业研究股票与 ETF 的价格证据身份清楚；生命周期结构地图和行业内研究排序可解释；资金轮动可回放；ETF 轮动是拥有独立证据、目标、风险和 Shadow 历史的策略版本。

## 阶段 7：运行加固

### 目标

让日常操作可恢复、可观察，同时不增加机构式仪式。

### 工作包

- 快照、SQLite、配置、模型和常设授权的备份/恢复；
- 启动恢复和券商对账演练；
- 数据/提供方中断与陈旧状态演练；
- MiniQMT L1 订阅、断线、重连、权限变化和行情缺口演练；
- Shadow/MiniQMT 断开和重复订单演练；
- 结构化日志和紧凑健康视图；
- 日更、页面加载、局部回测和模型预测性能基线；
- 依赖和密钥审查；
- 桌面/窄屏回归；
- 用户操作、事故处理和数据重建指南；
- 归档或替代失效文档。

### 退出条件

干净机器可以恢复本地状态；失败有清楚恢复路径；用户可以区分当前数据、当前策略、计划订单、券商状态和未解决异常。
