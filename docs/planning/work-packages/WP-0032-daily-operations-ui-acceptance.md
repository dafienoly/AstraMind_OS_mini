# WP-0032：系统页日常运行、异常处置与正式验收

- 版本：1.1.0
- 状态：已完成
- 需求：REQ-2026-0009 v1.2.0
- 上游：WP-0030 v1.1.0、WP-0031 v1.1.0
- 阶段：7
- UI 提案：UI-PROP-0008 v0.1、UI-PROP-0003 v0.1，均已批准
- 日期：2026-07-28
- 目标包：Daily Ops 1.0，第三里程碑
- 批准：用户于 2026-07-29 批准实施；严格复用 UI-PROP-0008/0003 v0.1
- 券商授权：无；界面不提供订单提交或撤单

## 目标

让用户在现有“系统”页看懂今天是否已完成、下一次何时运行、为什么受阻以及如何恢复，
并在“今日”异常收件箱只处理真正需要人工介入的日常运行异常。

## UI 边界

- 复用 UI-PROP-0008 v0.1 已批准的两列系统页，不新增一级入口；
- 显示目标交易日、当前步骤、最近成功、下次计划、耗时、阻断码和恢复动作；
- “运行今日任务”“恢复中断”“重试等待提供方”只向 WP-0030 同一控制库登记一次
  本地运行请求，HTTP 请求本身不得访问提供方或重算研究链；
- 同一运行已存在时按钮变为“查看运行”，不得重复登记；
- “今日”页只在超时、关键缺口、身份漂移或需要本机部署确认时出现异常；
- 不显示 Token、账户 ID、Windows 用户路径、真实行情、候选证券或订单载荷；
- 如果实施需要改变现有两列布局或新增大型页面，必须先将 UI-PROP-0008 升级到 v0.2
  并取得批准。

## 状态

- 未安装调度；
- 等待运行窗口；
- 等待提供方；
- 运行中及当前步骤；
- 当前；
- 陈旧；
- 阻断；
- 等待恢复；
- 租约占用；
- 调度暂停；
- API 断开。

未知状态不得使用绿色；颜色必须同时配合文字、符号或动作说明。

## 范围

- 增加只读运行历史、当前摘要和调度状态 API；
- 增加有 CSRF/来源边界的本地运行请求 API，但只写控制请求，不执行外部动作；
- 系统页增加运行状态、下一计划和有限恢复操作；
- 今日异常收件箱消费同一投影，不建立第二份状态；
- 刷新后恢复当前进度，不依赖页面内存；
- 捕获桌面和窄屏真实截图，并与批准提案比较；
- 完成 Daily Ops 1.0 的命令、API、浏览器、恢复和安全正式验收。

## 非目标

- 不提供数据库、日志全文或任务定义编辑器；
- 不显示研究候选、组合明细或 Paper 订单载荷；
- 不通过页面连接 MiniQMT、下单、撤单或启用 Live；
- 不修改 StandingMandate、资金或回撤规则；
- 不进入长线模型、生命周期或 ETF。

## 验收

1. Given 当日日常运行完成，When 打开系统页，Then 一屏显示目标日期、数据提交、决策链、
   备份状态、下次计划和“当前”结论。
2. Given 提供方未完成，When 刷新页面，Then 显示 `waiting_provider` 和下一有界补跑时间，
   不显示失败成功或触发研究链。
3. Given 进程中断，When 点击“恢复中断”，Then 只登记一个恢复请求；刷新后继续显示同一
   运行身份和步骤。
4. Given 同一任务已运行，When 重复点击或多标签页并发请求，Then 只保留一个控制请求，
   页面转为查看已有运行。
5. Given API 断开、状态损坏或调度未安装，When 查看系统/今日页，Then 显示明确阻断和
   本地恢复动作，不使用绿色未知状态。
6. Given 检查 DOM、网络、日志和券商台账，Then 页面没有提交/撤单按钮，请求路径没有
   Tushare 或 MiniQMT 调用，券商连接和写入次数均为零。
7. Given 桌面与 390px 窄屏，When 完成浏览器工作流，Then 无水平溢出，严重阻断置顶且
   所有操作可由键盘完成。

## 目标包退出条件

- 一个命令可以安全运行完整日常链；
- 本机调度可预览、部署、暂停和恢复，且不会触发券商动作；
- 系统页和今日异常收件箱使用同一持久投影；
- 合成中断、错过窗口、并发触发、提供方延迟和 API 断开均有可见恢复路径；
- `make check` 与浏览器正式验收通过；
- Paper 提交、撤单、Live、长线模型、生命周期和 ETF 仍明确未进入。

## 实施证据

- `GET /api/system/daily-operations` 合并数据管线、研究决策、统一运行、最近历史、调度
  部署和本地请求；系统页与“今日”不建立第二份状态；
- `POST /api/system/daily-run-requests` 校验本地 Origin 和显式动作头，只写 SQLite/WAL
  幂等请求，不调用提供方或研究链；
- 系统页保留 UI-PROP-0008 v0.1 两列布局，并增加数据→决策→备份运行轨道、最近运行和
  异常收件箱；手动刷新保持上一次投影，只局部显示刷新错误；
- 桌面与 390px 截图分别保存在
  `var/evidence/wp-0032-system-daily-operations.png` 和
  `var/evidence/wp-0032-system-daily-operations-mobile.png`，无页面级水平溢出；
- 聚焦 API、React 和 Playwright 测试通过，DOM 中没有提交、撤单、买入或卖出控制。
