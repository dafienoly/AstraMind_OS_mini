# WP-0022：Paper 金丝雀运行编排器

- 版本：1.1.0
- 状态：实现完成；真实运行仍等待有效授权窗口和准确数值确认
- 需求：REQ-2026-0010 v1.4.0、REQ-2026-0009 v1.3.0
- 阶段：4E、7
- UI 提案：不适用；本工作包只编排已有本地命令能力
- 日期：2026-07-29

## 目标

把 WP-0021 的多个安全命令压缩为两个无需复制内部身份的入口：

```bash
make paper-canary-run
make paper-canary-settle
```

早盘入口自动完成窗口等待、只读账户基线、行情提案、准确文本确认、短时批准、唯一提交、
状态轮询和 unknown 查询恢复。盘后入口自动发现唯一批准与意图，重新读取券商事实并生成
收敛报告。

v1.1 增加独立只读预检、有界新鲜 tick 等待和 Windows runner 脱敏诊断。预检只读取
当前授权、完整模拟盘账户基线和 L1 行情，不调用提案构建器、订单意图仓储或 Paper
写网关。

## 安全编排

- 只允许在提交窗口前15分钟内启动；更早启动、窗口过期或日期不符均失败关闭；
- 提交窗口到达后才连接只读账户和行情；
- `paper-canary-preflight` 可在窗口前运行，只报告授权窗口为 `upcoming` 或 `open`；
  授权过期则失败关闭；
- 行情 runner 在最多8秒的有界等待中轮询新 tick，只有市场时间距接收时间不超过3秒
  才返回；领域层和提交层的3秒阈值保持不变；
- Paper Windows runner 的 stdout/stderr 以32,000字符上限写入 Git 忽略目录，先删除
  账户选择器、密钥、本机用户目录和 Windows/WSL 私有路径；
- 阻断分别使用 `windows_interop_unavailable`、`qmt_not_connected`、
  `canary_quote_stale`、`invalid_runner_json` 和明确 timeout code；
- 确认文本必须准确等于：
  `批准 <证券> 买入<数量>股 限价<两位小数>，仅提交一次`；
- `y`、回车、模糊价格或旧提案不能形成 `PaperSubmissionApproval`；
- 批准最长有效2分钟且不越过当前授权截止时间，账户基线超过3分钟时重新开始并重新确认；
- 重启后如已存在 Paper 意图，入口直接恢复监控，不再执行 stage/approve/submit；
- `submission_unknown` 自动调用的只有 query recovery，永远没有第二次 submit；
- 每5秒有界查询状态；全部成交、拒绝或已撤进入终态；
- 授权截止前1分钟仍有剩余委托时只提示准确撤单文本，默认回车不撤；不启用自动撤单；
- `Ctrl+C` 只停止本地守护，不触发重提、撤单或其他券商动作；
- 盘后命令在15:00前拒绝运行，报告不收敛时冻结未来订单。

编排器直接消费 WP-0018～0021 已有不可变授权、提案、批准、意图、命令、观察和投影，
不建立第二套执行状态机或任务真相源。SQLite/WAL 中已有证据同时充当恢复检查点。

## 非目标

- 不取消用户对确切数值限价的最终批准；
- 不自动追价、重提或扩展证券/数量/窗口；
- 不默认自动撤单；
- 不提供 Live、实盘、信用或其他资产；
- 不新增后台常驻调度器或可写 UI；
- 不改变或延长任何已有授权实例；
- 自动化测试不真实连接 MiniQMT。

## 自动化证据

- 完整准确确认文本，模糊确认被拒绝；
- 只在准确窗口前15分钟内等待；
- 确切批准仍受2分钟和当前授权截止时间约束；
- 已存在意图时恢复分支不调用提交；
- unknown 只走恢复查询；
- 初始陈旧 tick 后收到新鲜 tick 时继续，等待期耗尽仍陈旧时明确阻断；
- WSL 互操作、QMT 未连接、JSON 损坏和超时具有互斥诊断码；
- stdout/stderr 留存会删除账户、密钥和用户路径；
- preflight 遇到陈旧行情、中断或超时时，提案、订单意图和券商命令写入均为零；
- 盘后自动身份发现复用 WP-0021 收敛检查。
