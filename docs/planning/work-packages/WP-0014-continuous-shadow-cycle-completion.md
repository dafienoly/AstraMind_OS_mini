# WP-0014：持续 Shadow 周期闭环

- 版本：1.0.0
- 状态：实现完成；首个生产周期仍等待真实交易日观察
- 需求：REQ-2026-0006 v1.3.0
- 阶段：4B
- UI 提案：不适用；不新增或修改页面
- 券商授权：无；纯本地 Shadow，`broker_actions_allowed=false`
- 日期：2026-07-28

## 目标

把 WP-0013 已启动的不可变 `OrderPlan` 从等待开盘推进到入口撮合、每日盘后估值、
10 交易日退出、终态报告与重启恢复，形成不依赖券商的完整持续 Shadow 状态机。

## 非目标与保护边界

- 不连接 MiniQMT 交易会话、账户或回调；
- 不调用下单、撤单，不创建 Paper/Live 常设授权；
- 不把盘后获得的日线数据描述成实时成交；
- 不伪造 2026-07-29 及之后尚未发生的生产观察；
- 不实施待批准的今日、组合或执行页面。

## 实现口径

- 每次推进绑定一个准确不可变 `DataSnapshot`，只读取其清单声明的
  `trade_calendar`、`daily_market` 与 `daily_tradability` Parquet；
- 入口和退出使用原始开盘价，按已冻结假设加入 5bp 滑点和日成交额 5% 容量上限；
- 涨跌停、停牌、无 Bar、T+1、现金和 100 股整数手继续失败关闭；
- 入口只尝试计划执行日一次；第 10 个观察交易日开盘尝试退出，不能卖出时逐日顺延；
- 收盘估值缺失时保留上一个已确认权益并记录明确阻断，不插值或伪造价格；
- 每日状态、执行事件和 `ShadowCycleCheckpoint` 追加写入 SQLite/WAL；
- 终态生成 `ShadowCycleResult`，包含收益、已实现盈亏、最大回撤、检查点和事件计数；
- 重复推进同一交易日返回同一检查点，不重复事件或状态。

## 稳定命令

```bash
make continuous-shadow-advance \
  CYCLE_ARTIFACT=var/research/continuous-shadow/<identity>/cycle.json \
  SNAPSHOT_ID=snapshot:sha256:<包含观察日的准确快照> \
  THROUGH_DATE=YYYY-MM-DD
```

命令只处理快照已经覆盖的完成交易日。当前日期仍早于首周期的计划执行日
2026-07-29，因此生产验收正确返回 `waiting_next_open`，没有生成成交或检查点。

## 验收证据

- 合成 10 日周期证明入口、逐日估值、第 10 日退出、终态报告、幂等和重启恢复；
- 合成停牌场景证明退出顺延且缺失收盘价不会伪造估值；
- 精确快照读取测试证明只使用清单中声明的数据版本和路径；
- 原有持续 Shadow、T+1、回撤和订单计划测试继续通过；
- `broker_actions_allowed` 在周期、检查点和结果中始终为假。

## 关闭条件

实现与合成验收已经完成。首个生产周期必须在 2026-07-29 及后续完成交易日逐日推进，
真实形成入口或可解释的不入场证据，并在达到退出终态后才能把“生产周期运行验收”标为
完成；在此之前不得伪造日期、行情、成交或收益。
