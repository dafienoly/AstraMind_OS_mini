# WP-0060：业务文案门面与折叠技术详情

- 版本：1.0.0
- 状态：已批准，待实施
- 需求：REQ-2026-0003 v1.8.0、REQ-2026-0008 v2.2.0
- 阶段：6、7
- UI 提案：复用当前准确布局；只改变文案层级和折叠详情
- 所有者：Web 展示层

## 目标

建立统一、类型化的“内部状态 → 中文业务文本”门面，主界面不再裸露枚举、提供方
路由、完整哈希或 `known_gaps` 原因码；原始技术值仅在折叠“技术详情”中显示。

## 首批固定映射

| 内部值 | 主界面业务文本 |
| --- | --- |
| `ready` | 数据可用 |
| `unavailable` | 暂无可用数据 |
| `date-bound-cutover` | 历史行情与实时行情已衔接 |
| `miniqmt` | MiniQMT 实时行情 |
| `sha256:...` | 数据版本；主界面默认显示更新时间 |
| `historical_membership_not_then_known` | 缺少当时可知的历史行业归属，暂不能进行严格历史验证 |
| `v2_not_trained` | 学习模型尚未形成生产结果，当前使用规则模型 |
| `CURRENT / STALE / DISCONNECTED` | 正在更新 / 更新延迟 / 实时连接中断 |

## 允许文件

- 新建单一用途业务文案模块及其测试
- 现有市场、生命周期、行业排序、ETF、相对轮动和通用个股组件
- 对应组件/E2E 测试

## 验收

1. 主界面扫描不出现完整 SHA-256、原始 `known_gaps`、内部枚举或路由标识。
2. 未登记的内部代码以“暂无法解释的系统状态”失败关闭，并在技术详情保留原值。
3. 技术详情默认折叠，展开后明确标注“用于诊断”，不与业务结论同层。
4. 同一内部状态在全部页面使用同一业务文本和可访问性标签。
5. 不新增页面、导航、交易动作或模型结果。

## 冲突边界

不修改 `RealtimePulse.tsx` 的交易时段状态机、不调整历史查询接口、不改共享设计
tokens；这些分别由 WP-0058、WP-0059 和主控对话负责。
