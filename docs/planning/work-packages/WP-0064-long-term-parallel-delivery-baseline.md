# WP-0064：长期并行交付基线

- 版本：1.0.0
- 状态：已批准实施；本包只建立规划与主控基线
- 需求：REQ-2026-0004 v2.8.0、REQ-2026-0005 v1.4.0、REQ-2026-0006 v2.1.0、
  REQ-2026-0007 v2.3.0、REQ-2026-0008 v2.2.1、REQ-2026-0009 v1.4.0、
  REQ-2026-0010 v2.1.0、REQ-2026-0014 v1.0.0
- 阶段：跨阶段 2～7 的交付治理
- UI 提案：不适用
- 所有者：主控工作区

## 目标

把当前需求、已完成能力、未开发能力、数据门、授权门和三条永久工作树组织成一条
可持续交付列车。主控在每次集成后都能从权威阶段计划确定下一包，不依赖会话记忆，
也不把“已规划”误写成“已授权实施”。

## 非目标

- 不实现因子、策略、Research Shadow、Paper 分仓、行情采集或用户界面；
- 不连接 MiniQMT，不读取账户，不产生模拟盘或实盘订单；
- 不替代各功能 WP 的目标、允许文件、测试和验收；
- 不一次性创建大量空 WP 文件；尚未释放的包只在阶段计划中保留编号和边界。

## 永久工作线

| 通道 | 长期主责 | 高争用边界 |
| --- | --- | --- |
| Worker A | Data、实时行情、市场模型生产链 | 数据快照契约、数据脚本及当前 MiniQMT 重构必须单所有者 |
| Worker B | 短线研究、Research Shadow、策略选择 | 与 Trading Execution 共用的 OrderPlan/账本只能合同先行、串行接入 |
| Worker C | 周度核心因子、模型、组合政策 | F0/Alpha158/Alpha101 先独立包，联合只消费 selected |
| 主控 | 需求/WP、基线同步、复核、集成、授权门和下一波派发 | 阶段计划、决策记录、公共契约、组合根、迁移和注册表 |

临时 UI 包可以使用空闲通道，但完成后通道必须回归长期主责。每一波都从主控最新集成
提交建立新分支；永久工作树不会自动获得主线新提交，主控必须在派发前显式同步。

## 释放规则

1. `可自动续派`：需求已批准、实施已授权、无新 UI、无生产数据变更、无 MiniQMT
   新调用、无账户或券商动作，并且文件边界不与运行中的包冲突。
2. `待实施授权`：需求语义已定，但 REQ 明确写明功能、UI 或迁移未授权。只允许保留
   编号、依赖和验收轮廓，不得进入代码工作树。
3. `待数据门`：可以实现失败关闭和证据检查，但不能伪造训练样本、预测或晋级结果。
4. `受保护`：生产数据补采、MiniQMT 新调用、Paper/Live、账户或真实订单必须取得
   对应精确授权，长期推进目标不扩大这些权限。
5. REQ-2026-0011～0013 保持 R0 后挑战包，不进入当前关键路径。

## 主控循环

1. 检查 Worker A/B/C 与登记任务的游标、提交、未提交成果和测试；
2. 只复核刚完成的新成果，确认文件范围、数据身份、测试和受保护动作；
3. 集成后运行受影响范围检查，更新唯一追踪表、WP 结果和阶段计划；
4. 从最新主线建立下一波分支并同步空闲永久工作树；
5. 只派发已经释放且边界不冲突的下一包；否则报告唯一授权门或数据门；
6. Paper/Live、生产补采和 UI 批准不因自动循环而被绕过。

## 验收

1. 阶段计划包含唯一的未开发能力矩阵、预留 WP、依赖、授权状态和三通道波次；
2. 需求索引、REQ 状态、现有 WP 状态和决策记录不再保留已失效的 P0/旧 UI 描述；
3. 任一新会话只读本包与阶段计划即可判断“现在做什么、下一步做什么、为何被阻断”；
4. 当前 WP-0062/0063 不被中断，MiniQMT 数据管线重构不被并行修改；
5. `make docs-check` 通过。

## 保护边界

本包是交付治理授权，不是后续所有功能的总授权。每个功能包仍必须满足对应 REQ 的
实施授权、UI 批准、数据门和券商保护边界。
