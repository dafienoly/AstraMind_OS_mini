# WP-0002B-H1：复用旧 Silver 的历史日线与复权因子

- 状态：已完成
- 需求：REQ-2026-0001 v1.0.1
- 父工作包：WP-0002B
- 阶段：2B 历史行情切片
- UI 提案：不适用
- 数据源：旧 AstraMind 正式 Silver + Tushare 缺口补充

## 目标

将 2000 年以来的不复权日线和复权因子纳入 Mini 的不可变 `DataSnapshot`。优先复用
旧 AstraMind 已通过正式研究发布的数据，只对缺失交易日联网补数。

## 实际来源

旧版本 `a-share-daily-v1-20260724-4e1f5f6ae28d` 的状态为
`passed_for_formal_research`：

- `daily`：6,434 个交易日分区、17,113,982 行；
- `adj_factor`：6,434 个交易日分区、17,691,084 行；
- 覆盖 2000-01-04 至 2026-07-24；
- 每行保留旧任务身份、原始响应 SHA256 和旧数据集版本。

与 Mini 固定交易日历相比只缺 2026-07-15。本工作包只为该日调用 Tushare
`daily` 和 `adj_factor`，没有重复拉取 2000 年以来的数据。

## 实现

- 旧 Silver 只读发现器只接受正式通过且具有发布内容身份的版本；
- DuckDB 按自然年流式转换为 Mini Schema，不把完整历史载入 Python 内存；
- Git 忽略的原子 `state.json` 记录已封存年度和补充日期，支持中断后继续；
- 完成任务再次执行直接返回原快照，不联网、不产生新版本；
- 历史 `available_at` 固定为交易日 18:00（Asia/Shanghai），`retrieved_at`
  单独记录 Mini 导入时间；
- 年度文件通过文件哈希发布，使用硬链接避免暂存与正式目录重复占用；
- DuckDB 多分区查询只接受清单明确列出的文件，不使用目录扫描或 glob；
- 最终先发布不可变数据集与快照，再原子切换 `current/data-snapshot.json`。

## 保留的必要校验

- 交易日覆盖必须等于固定日历；
- 年度 `(instrument_id, trade_date)` 主键唯一；
- OHLC、成交量、成交额和正复权因子满足基本约束；
- 每条日线必须存在复权因子；
- 最终清单、文件哈希和当前快照指针一致。

没有增加复杂作业状态机、逐文件重复验签、历史数据重复联网或新的 SQLite 迁移。
