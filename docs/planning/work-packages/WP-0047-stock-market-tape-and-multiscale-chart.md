# WP-0047：个股全景行情与多时标检查器

- 版本：1.0.0
- 状态：已批准实施；代码验收已完成，待更新既有任务定义并完成真实连续竞价 15 分钟
  与页面端到端 P95 运营验收
- 需求：REQ-2026-0004 v2.9.0、REQ-2026-0008 v2.2.1、
  REQ-2026-0009 v1.5.0
- 阶段：6A、6B
- UI：复用已批准 UI-PROP-0001 v0.7；只实现其中既定多周期检查器和真实运行状态，
  不改变导航、布局或视觉方向

## 目标

恢复 MiniQMT 只读实时服务的可运营状态，并以用户提供的个股行情截图为字段参考，
把个股观察扩展为截图数据的可审计超集：
当前报价、当日统计、L1/L2 行业、盘中派生估值、多时标 K 线、成交量、技术指标、
五档盘口和来源证据使用同一证券、会话、参考日与新鲜度语义。

## 已发现冲突

数据契约和 WP-0041/0046 声明“全 A 股长期保存一分钟 OHLCV/成交额”并已实现，但
2026-07-29 本地审计发现：

- `var/data/realtime/miniqmt/aggregates/1m/` 只有日期目录，没有聚合文件；
- 原始和规范化会话微批存在，但现存大样本为收盘后累计快照，无法反推日内分钟路径；
- 当前证券 API 只按投影 `market_date` 读取一分钟数据，不支持跨日、频率聚合或
  历史暖启动；
- 因此当前页面不能可靠提供截图中的 5 分钟 MA60、MACD 或 5 日分钟视图。

在分钟暖启动、持续聚合、跨重启恢复和内容哈希验收完成前，文档中的“已留存一分钟
K 线”只能视为目标契约，不能作为已完成运营能力。

## 非目标

- 不读取账户、持仓、委托或成交；
- 不创建订单，不增加交易按钮；
- 不复制第三方论坛、问答、F10 或社交入口；
- 不把盘中派生 PE、市值或换手率写回完成日 `DataSnapshot`；
- 不用日内高低或板块规则猜测涨跌停；
- 不在种子窗口不足时计算缩短窗口的 MA/MACD。

## 数据工作

1. 常驻桥一次批量读取证券合约资料，规范化 `FloatVolume`、`TotalVolume`、
   `UpStopPrice`、`DownStopPrice`、`InstrumentStatus`、`IsTrading` 和资料日期；
2. 当前证券投影关联最近完成日 `daily_basic`，保留估值、股本来源和参考日；
3. 盘中派生换手率、PE(TTM)、总/流通市值，契约显式记录 `derived`、公式版本和
   参考日；
4. 当前行业身份扩展为点时 SW2021 L1/L2，并分别聚合盘中临时涨跌；
5. 服务启动时从 MiniQMT 热缓存补取当日全市场 1 分钟历史，随后用 L1 增量原位更新
   形成中 Bar；批量写入内容寻址的一分钟分区；
6. 跨重启按证券、市场分钟去重，保留提供方、会话、市场时间、接收时间、量额单位、
   缺口和内容哈希；
7. 当前详情 API 支持 1/5/15/30/60/120 分钟和最近五个交易日；高频周期只由完整
   1 分钟源确定性聚合；
8. 日/周/月/年复用完成日 `daily_market` 与共享价格检查器，不创建第二套历史价格
   查询。

## 运行恢复与可观测性

1. 计划任务查询使用 `installed / not_installed / query_failed` 三态；Windows/WSL
   互操作失败不得覆盖最后已知安装事实；
2. 状态投影分离计划任务、WSL 进程、MiniQMT 会话、当前投影和完成日数据，不再用一个
   `stale/not_installed` 同时表达不同故障；
3. 有界重试逐次保留错误类型和脱敏消息，终止状态暴露最后具体根因；不得用通用
   “没有创建行情会话”吞掉桥接错误；
4. Windows 计划任务的 stdout/stderr 写入有界轮转日志，状态文件原子记录最后成功
   心跳、最后消息/微批时间、退出码和恢复建议；
5. 修复后再重新启动既有只读任务并完成真实交易时段观察；不得卸载任务来掩盖失败。

## 分钟与多周期口径

1. 主键为 `provider + session_id + instrument_id + market_minute`；同一证券分钟的暖启动
   与 L1 增量按来源优先级和内容身份对账，重复运行幂等；
2. 原始 MiniQMT 返回、规范一分钟观察、形成中投影和收盘封存制品分别保存；每层记录
   provider、source identity、retrieved/received/market time、单位、schema、缺口和
   内容哈希；
3. 上午以 09:30、下午以 13:00 独立锚定 5/15/30/60/120 分钟桶，禁止跨午休；
   120 分钟分别对应 09:30–11:30、13:00–15:00；
4. 仅完整源分钟生成闭合高周期 Bar；源缺口产生显式不完整状态，不前填、不缩短窗口；
5. API 接受频率、证券、起止日期或最近会话数，首期最多返回最近五个交易日并使用稳定
   游标/日期窗；当前形成中 Bar 由 SSE 增量更新，历史闭合 Bar 由 GET 加载；
6. MA/MACD 只在足够闭合种子上计算；频率切换、五日视图、Loading、延迟、断线和
   `insufficient_seed` 完全复用 UI-PROP-0001 v0.7 的既定位置。

## 验收

1. 用户截图中的全部行情字段都有 `direct / reference / derived / unavailable` 状态；
2. 有研新材实际快照可复现 39.86、-8.37%、43.09/43.28/39.15、113.69 万手和
   45.80 亿元；派生换手、PE 和市值明确使用 2026-07-28 基准；
3. 当日服务在任意交易时刻启动，已发生分钟可由缓存恢复，后续分钟由订阅持续维护；
4. 重启前后一分钟主键无重复，累计量额不跨会话产生负增量或重复增量；
5. 5/15/30/60/120 分钟 OHLCV/成交额与 1 分钟源确定性一致；
6. MA 与 MACD 在足够种子窗口下结果稳定，窗口不足返回 `insufficient_seed`；
7. 合约资料或完成日基准缺失时，对应值为空并登记缺口，其余实时字段继续可用；
8. 若后续改变现有个股工作面布局，先提交新 UI 提案；仅后端接线时复用现有工作面并
   验证 Loading、Stale、Disconnected 和分钟不足状态；
9. 全程只导入 `xtquant.xtdata`，不增加账户或交易接口。
10. 计划任务查询失败显示 `query_failed` 而非 `not_installed`；桥接失败的终止根因、
    最后成功心跳和日志路径可由本地状态接口读取；
11. 暖启动与 L1 重叠一分钟、同日重启、午休重启和收盘封存均有负例/幂等测试；
12. 多周期 golden 覆盖上午、午休边界、下午、缺一分钟、停牌无成交、累计量额重置和
    跨日，OHLCV/成交额与独立一分钟 oracle 一致；
13. 后端单元/集成、前端组件测试和浏览器可见流程通过；真实连续竞价观察至少 15 分钟，
    页面端到端 P95 不高于 2 秒，证据单独记录，不能由合成测试替代。

## 保护边界

本包仅授权本机只读行情、参考数据关联、运行恢复和既有批准界面的派生展示。只允许
`xtquant.xtdata` 行情能力，不读取账户、资产、持仓、委托或成交，不下单、不撤单，
不启用 Paper/Live。任何超出 UI-PROP-0001 v0.7 的个股工作面信息层级变化仍须新的
准确 UI 提案。
