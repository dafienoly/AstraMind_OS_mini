# REQ-2026-0001：初始产品基线

- 需求版本：1.0.1
- 状态：已批准（规划）
- 来源：截至 2026-07-26 的用户规划对话
- 本次澄清：2026-07-27，MiniQMT 当前能力转由 REQ-2026-0004 记录
- 实现状态：规划基线已完成；WP-0007 已完成收口
- 开发队列：已退出；继续作为产品、架构、数据、授权和开发治理的持续约束
- 追踪：见[需求索引唯一追踪表](./README.md#唯一追踪表)
- 目标：仓库基础与分阶段路线图

## 目标

在实施前建立一个小型、本地优先的 A 股量化交易项目，并明确数据、研究、组合、执行和界面边界。

## 范围内

- 仓库与文档基础。
- 产品、领域、架构、数据、界面和交付基线。
- 短线 5 万元、长线 10 万元两个分仓。
- 个股优先、本地 Shadow、策略手动晋级。
- 龙虎榜、股东户数、财务数据、市场/行业状态和 ETF 生命周期边界。
- 包含大盘与行业看板的五入口信息架构。
- 界面先出示意图、后实施。
- Vibe Coding 的文件、依赖、工作包和冲突控制。

## 范围外

- 应用源代码和可运行数据拉取。
- 任何实际界面实现。
- 券商连接、Paper、Live 或真实资金。
- 所有策略参数或模型超参数的最终选择。
- 任何策略已经盈利或具备实盘资格的声明。

## 功能要求

1. 仓库必须提供唯一权威文档入口。
2. 系统必须分离数据、市场状态、策略研究、组合与风险、交易执行五个上下文。
3. 个股交易优先于 ETF 轮动。
4. 短线分仓按 5 万元规划，常态持有 1–2 只股票。
5. 长线分仓按 10 万元规划，常态约 5 只股票，按周评估。
6. 多类短线策略可以并行运行和比较。
7. 龙虎榜作为盘后事件输入，股东户数作为点时正确的慢速上下文输入。
8. 行业生命周期作为市场研究和 ETF 轮动的版本化上游证据。
9. 本地 Shadow 与未来券商网关必须共享订单计划语义。
10. 用户可以手动晋级策略，不强制等待固定 20 天 Shadow。
11. 策略晋级必须与券商和资金授权分离。
12. 未来常设授权范围内的例行动作不逐笔审批，异常必须可见。
13. 初期一级入口只能是今日、市场、策略竞技场、组合和系统。
14. 市场包含大盘、行业和后续 ETF 轮动。
15. 所有重要界面必须先有版本化示意图，并经用户明确批准。
16. Coding Agent 必须在有限工作包内工作，并保持上下文单向依赖。
17. 默认受影响范围检查目标为 90 秒以内。
18. MiniQMT、Paper、Live、常设授权和真实订单必须在相应阶段单独批准。
19. 面向用户的产品、需求、规划、架构、数据和 UI 文档使用简体中文；仅明确列出的 Agent/Vibe 内部文档可保留英文。

## 验收标准

### 文档

Given 仓库只有规划文件，When 打开 `docs/README.md`，Then 本需求引用的所有权威基线都能通过有效相对链接找到。

Given 一项计划变更，When Coding Agent 遵循 `AGENTS.md`，Then 可以定位受影响上下文、需求、阶段和 UI 提案，无需依赖旧 AstraMind 仓库。

Given 新增或修改面向用户的文档，When 检查语言边界，Then 正文为简体中文，代码标识和专有名词除外。

### 领域与数据

Given 同一股票预测，When 分别讨论研究、组合与执行，Then 使用 `StrategyVersion`、`PortfolioTarget` 和 `OrderPlan` 表达不同概念。

Given 一条股东户数记录的报告期早于公告日，When 历史决策发生在公告日前，Then 该记录不可用。

Given T 日盘后龙虎榜事件，When 生成执行假设，Then 不得使用 T 日更早价格成交。

### 界面

Given 一个新页面没有已批准示意图，When 准备实施，Then 只能创建提案产物，不能写界面代码。

Given 已批准的界面提案，When 开始实施，Then 工作包必须引用准确版本，完成后提供真实截图对比。

### 执行

Given 只有文档、回测或本地 Shadow 产物，When 没有独立券商授权，Then 不得发生 MiniQMT 连接或券商副作用。

Given 未来订单超出常设授权，When 进入执行计划，Then 它必须进入异常处理，而不是静默执行。
