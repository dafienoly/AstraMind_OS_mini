# REQ-2026-0004：东莞证券 MiniQMT 能力接入路线

- 需求版本：1.1.0
- 状态：已批准（规划）
- 批准日期：2026-07-27
- 来源：用户确认本机东莞证券 MiniQMT 已打通，并要求充分利用其能力
- 目标阶段：阶段 2、4、7
- 实现状态：部分实施；WP-0002A 能力探测、WP-0002C L1 实时微批和 WP-0011
  真实模拟盘只读账户/对账验收已完成；Paper、Live 和真实订单未授权
- 追踪：见[需求索引唯一追踪表](./README.md#唯一追踪表)

## 目标

把本机已验证的东莞证券 MiniQMT 行情和账户能力纳入 AstraMind OS Mini，
形成可追溯的实时行情来源、可恢复的模拟盘路径和受保护的实盘网关，同时保持
研究、组合、风险和执行边界不变。

## 范围内

- MiniQMT 行情能力与交易能力使用两个逻辑端口：
  - Data 上下文的行情/资料适配器；
  - Trading Execution 上下文的账户/委托/回调适配器。
- L1 全推、订阅/退订、最新 Tick、日内连接状态、断线重连和缺口可见性。
- K 线、Tick、历史下载、交易日历、合约、板块/行业/指数权重、财务、复权因子、
  ETF/可转债资料的逐数据集能力核验。
- 模拟盘与实盘账户的资金、持仓、委托、成交和账户状态读取。
- 股票委托与撤单的同步/异步适配，以及委托、成交、资产、持仓回调。
- Shadow → 模拟盘 Paper → 有限 Live 的分级验证和启动对账。
- 本地缓存、重启恢复、幂等、重复回调、断线和陈旧行情处理。

## 范围外

- 在未获工作包授权时连接或调用 MiniQMT；WP-0002A、WP-0002C 和 WP-0011 是已记录
  例外。
- 自动或周期性读取真实账户、启用模拟盘下单、启用 Live 或提交首笔真实订单；
  WP-0011 只允许一次有界只读查询与本地对账。
- 融资融券、约券、期货、期权或其他非 A 股股票执行。
- 把 MiniQMT 本地缓存直接当作研究真相源。
- 用实时行情绕过策略证据、组合构建、风险或常设授权。
- 因 MiniQMT 可提供某字段而停止 Tushare 或其他来源的逐数据集质量比较。

## 功能要求

1. 系统必须记录一次版本化能力探测，区分接口存在、权限可用、数据可用和已通过验收。
2. 行情适配器必须保存来源、RPC/客户端身份、行情级别、市场时间、接收时间、订阅会话、
   权限和缺口，不得用接收时间冒充市场时间。
3. 实时流必须支持显式订阅/退订、断线检测、重连、重复消息去重和可见的陈旧状态。
4. 实时 Tick、K 线和历史下载必须进入 Data 上下文的原始/标准化分层；本地缓存只是
   提供方缓存，不是第二个快照真相。
5. 同一研究或交易请求仍只能固定一个不可变 `DataSnapshot`；混用 Tushare 与
   MiniQMT 时，清单必须逐数据集记录提供方和版本。
6. L2 数据必须默认关闭；没有权限、字段不全或连续性不足时失败关闭并回退到明确标记的
   L1 能力，不得伪装成 L2。
7. 账户读取必须明确区分模拟盘与实盘，并生成带 `as_of` 的只读账户快照；账户标识和
   凭据不得进入日志、Fixture、API 响应或截图。
8. MiniQMT 交易适配器只能消费已经通过风险和授权判断的不可变 `OrderPlan`，不能导入
   策略、模型或优化器。
9. 同步/异步下单、撤单和回调必须映射到同一 `ExecutionEvent` 状态模型，使用幂等键并
   处理重复、乱序、迟到和重连补报。
10. 每次启动 Paper/Live 前必须先读取账户、持仓、未完成委托和当日成交并完成对账；
    差异未解决时阻断新订单。
11. 本地 Shadow 必须先用相同订单计划和实时行情跑通；随后才能在单独授权下进入模拟盘
    Paper，再在独立授权下进入有限 Live。
12. 实时行情、账户或回调断开时，系统必须显示 Disconnected/Stale/Blocked，停止依赖
    新鲜行情或未完成对账的动作，未知状态不得显示为健康。

## 架构与数据约束

- 一个本地 MiniQMT RPC 桥可以承载行情与交易协议，但必须向系统暴露独立端口、配置、
  健康状态和测试替身。
- 领域契约不得导入 MiniQMT SDK、RPC 客户端或 Windows 路径。
- 原始行情/查询响应只追加；标准化观察、账户快照和执行事件分别归属 Data 与
  Trading Execution。
- MiniQMT、Tushare 和其他来源冲突时不得静默择值；数据集策略必须版本化并输出差异。
- WSL 服务继续只绑定回环地址，凭据只通过本地秘密配置进入隔离网关。

## 验收标准

### 行情与数据

Given 只有 L1 权限，When 启动行情适配器，Then L1 全推可用且 L2 明确显示不可用，
系统不生成伪 L2 数据。

Given 行情 RPC 断开，When 数据超过新鲜度阈值，Then 下游看到 Stale/Disconnected，
恢复后新会话身份和缺口范围可追溯。

Given 一个快照混合 Tushare 历史与 MiniQMT 实时数据，When 查看清单，Then 每个数据集
都有独立提供方、版本、可用时间、内容哈希和已知缺口。

### 账户与执行

Given 同时存在模拟盘和实盘，When 查询账户，Then 返回结果明确标记账户模式且不暴露
真实账户标识。

Given 没有本工作包级账户授权，When 应用准备调用账户查询，Then 失败关闭且不发出 RPC。

Given 同一异步委托回调重复或乱序到达，When 映射执行事件，Then 事件幂等、顺序可解释，
订单状态不回退。

Given 启动对账存在持仓或未完成委托差异，When 准备提交新订单，Then 新订单被阻断并显示
可行动的差异原因。

Given 只有本需求批准，When 尝试 Paper 或 Live 下单，Then 系统拒绝并要求对应受保护批准。

### 证据

- 行情和账户端口合同测试；
- RPC 录制 Fixture 的脱敏与许可证审查；
- 断线、重连、重复、乱序、陈旧和权限不足负例；
- Shadow/Paper 使用同一 `OrderPlan` 的契约证据；
- Live 前的只读探针、启动对账、急停和首单检查单；
- 文档、日志和 Fixture 密钥扫描通过。

## 兼容与回退

- MiniQMT 不可用时，历史研究继续使用已发布的不可变数据快照。
- 实时功能进入 Disconnected/Stale，不自动切换到来源不明的“最新值”。
- Paper/Live 网关故障只影响执行适配器，不改变策略、组合或既有事件历史。
- 任一数据集只有在覆盖、时间语义和质量优于或补充现有来源时才纳入正式快照策略。
