## 目标

把本机已验证的东莞证券 MiniQMT 行情和账户能力纳入 AstraMind OS Mini，
形成可追溯的实时行情来源、可恢复的模拟盘路径和受保护的实盘网关，同时保持
研究、组合、风险和执行边界不变。

## 范围内

- MiniQMT 行情能力与交易能力使用两个逻辑端口：
  - Data 上下文的行情/资料适配器；
  - Trading Execution 上下文的账户/委托/回调适配器。
- L1 全推、订阅/退订、最新 Tick、日内连接状态、断线重连和缺口可见性。
- 当前会话投影、不可变实时微批和收盘封存分钟/日频数据集的分层产品语义。
- 根据已冻结日频粗筛候选，按统一参数补拉分钟/Tick 并形成候选级研究快照。
- K 线、Tick、历史下载、交易日历、合约、板块/行业/指数权重、财务、复权因子、
  ETF/可转债资料的逐数据集能力核验。
- 模拟盘与实盘账户的资金、持仓、委托、成交和账户状态读取。
- 股票委托与撤单的同步/异步适配，以及委托、成交、资产、持仓回调。
- 历史回测/封存回放 → Research Shadow → 显式在位政策 → 模拟盘 Paper → 有限
  Live 的分级验证和启动对账。
- 本地确定性回放只作为 Local Replay 测试端口；Research Shadow 是 Strategy
  Research 的独立候选证据，不是 MiniQMT 或执行模式。
- 本地缓存、重启恢复、幂等、重复回调、断线和陈旧行情处理。

## 范围外

- 在未获工作包授权时连接或调用 MiniQMT；WP-0002A、WP-0002C、WP-0011 和 WP-0017

- 自动或周期性读取真实账户、启用模拟盘下单、启用 Live 或提交首笔真实订单；
  WP-0011 只允许有界只读查询与本地对账；WP-0017 只允许准确模拟盘的完整基线和
  回调订阅、静默观察、退订生命周期。
- 融资融券、约券、期货、期权或其他非 A 股股票执行。
- 把 MiniQMT 本地缓存直接当作研究真相源。
- 用实时行情绕过策略证据、组合构建、风险或常设授权。
- 由策略模块直接调用 MiniQMT，或按人工看图后的关注度临时决定研究数据范围。
- 把当前会话投影、未封存分钟 Bar 或提供方缓存直接用于回测、训练或策略晋级。
- 因 MiniQMT 可提供某字段而停止 Tushare 或其他来源的逐数据集质量比较。

## 功能要求

1. 系统必须记录一次版本化能力探测，区分接口存在、权限可用、数据可用和已通过验收。
2. 行情适配器必须保存来源、RPC/客户端身份、行情级别、市场时间、接收时间、订阅会话、
   权限和缺口，不得用接收时间冒充市场时间。
3. 实时流必须支持显式订阅/退订、断线检测、重连、重复消息去重和可见的陈旧状态。
4. 实时 Tick、K 线和历史下载必须进入 Data 上下文的原始/标准化分层；本地缓存只是
   提供方缓存，不是第二个快照真相。
5. 同一研究或交易请求仍只能固定一个不可变 `DataSnapshot`；混用 Tushare 与
   MiniQMT 时，清单必须逐数据集记录提供方和版本。
6. L2 数据必须默认关闭；没有权限、字段不全或连续性不足时失败关闭并回退到明确标记的
   L1 能力，不得伪装成 L2。
7. 账户读取必须明确区分模拟盘与实盘，并生成带 `as_of` 的只读账户快照；账户标识和
   凭据不得进入日志、Fixture、API 响应或截图。
8. MiniQMT 交易适配器只能消费已经通过风险和授权判断的不可变 `OrderPlan`，不能导入
   策略、模型或优化器。
9. 同步/异步下单、撤单和回调必须映射到同一 `ExecutionEvent` 状态模型，使用幂等键并
   处理重复、乱序、迟到和重连补报。
10. 每次启动 Paper/Live 前必须先读取账户、持仓、未完成委托和当日成交并完成对账；
    差异未解决时阻断新订单。
11. Local Replay 必须用相同 `OrderPlan` 完成状态机、风险、幂等和恢复测试；
    Research Shadow 必须按 REQ-2026-0014 隔离多候选账本；只有在位政策的券商执行
    和运营成熟度可以进入单独授权的 MiniQMT Paper。
12. 实时行情、账户或回调断开时，系统必须显示 Disconnected/Stale/Blocked，停止依赖
    新鲜行情或未完成对账的动作，未知状态不得显示为健康。
13. 日度与历史采集必须使用规范数据集请求；一次运行开始时冻结逐数据集选源路由，
    应用服务不得直接决定 Tushare 或 MiniQMT 原生接口。
14. 主源失败时只能整数据集回退，禁止逐行补值；原始失败响应、回退原因和最终来源
    必须进入追加式证据。
15. MiniQMT 成为主源前原则上必须在完整生产范围通过点时、覆盖、字段、单位和性能
    门禁；P95 至少快两倍且吞吐至少两倍。用户可因成本或供应商依赖明确批准数据集级
    例外，但必须记录未通过项、报告身份和 Tushare 整批回退，不得静默降低门禁。
16. 同一数据集版本不得混用提供方；切源必须先发布完整单源基线，不能把 MiniQMT
    新增记录拼入仍由 Tushare 构成的历史版本。
17. 实时 L1 原始与逐条规范化细粒度负载保留五个上海交易日；删除前必须验证长期
    一分钟聚合，永久保留会话/微批清单、内容哈希、缺口和删除台账。一秒市场/行业
    结果只维护当前投影，不建立长期分区。
18. 系统必须区分当前会话投影、不可变实时微批和收盘封存日内数据集；三者分别记录
    市场时间、接收时间、会话、来源、覆盖、缺口和内容身份，当前投影不得冒充完成日
    `DataSnapshot`。
19. 每个拟接入的日线、分钟、Tick、盘口或资料数据集必须登记字段、频率、复权/单位、
    市场与可用时间、历史起点、权限、调用限制、保留期和质量门；接口存在不等于研究
    可用。
20. 候选级日内请求必须引用一个先于日内取值冻结的日频粗筛身份，并固定候选全集、
    证据截止、字段、频率、回看窗口、复权口径、质量策略和请求版本。
21. Strategy Research 只能提交提供方中立的规范请求；MiniQMT SDK、原生字段和调用
    时序只能存在于 Data 适配器及隔离桥。
22. 同一次候选请求必须覆盖完整冻结候选集。传输缺页、权限不足、字段不全或无法解释
    的空响应先触发整数据集提供方回退；合法停牌/无成交保留真实状态。失败候选不得被
    下一名或人工关注标的静默替换。
23. 重复请求必须按冻结参数与内容哈希幂等复用；提供方后续返回不同内容时发布新版本
    和差异证据，不得覆盖旧研究快照。
24. 历史日内研究必须先在每个历史决策日用点时日频数据重放粗筛，再请求该日冻结候选
    在证据截止前的数据；当前证券列表、后验赢家或人工看图结果不得决定历史样本。
25. 只有覆盖和截止校验通过并完成封存的分钟/Tick 数据集可以进入 `DataSnapshot`；
    当前会话投影只服务盘中观察、风险预检和显式临时诊断。

## 架构与数据约束

- 一个本地 MiniQMT RPC 桥可以承载行情与交易协议，但必须向系统暴露独立端口、配置、
  健康状态和测试替身。
- 领域契约不得导入 MiniQMT SDK、RPC 客户端或 Windows 路径。
- 原始行情/查询响应只追加；标准化观察、账户快照和执行事件分别归属 Data 与
  Trading Execution。
- MiniQMT、Tushare 和其他来源冲突时不得静默择值；数据集策略必须版本化并输出差异。
- WSL 服务继续只绑定回环地址，凭据只通过本地秘密配置进入隔离网关。

## v2.8 数据完整性、历史访问与市场会话语义

### P0：不可变制品恢复

- 可变工作文件与已发布内容寻址制品不得共享 inode；禁止把后续仍会改写的文件通过
  硬链接发布到不可变目录；
- 发布前后复核字节哈希、行数、主键和日期范围，任一不一致都阻断指针切换；
- 已发现共享 inode 的历史版本保留身份和审计记录，但暂停用于正式 V2 训练、封存
  回放与晋级证据，必须重新发布新版本和新 `DataSnapshot`；
- 2026-07-29 当前快照恢复由 WP-0057 承接，恢复不得静默改写旧清单。

### P1：完整历史

- 股票从上市日或最早可靠记录开始，指数从正式发布日期或最早可靠记录开始，ETF 从
  上市日或最早可靠记录开始；
- API 采用明确日期窗口或游标分页，单次可以限流，但不得用固定 300/520 根冒充完整
  历史；
- ETF 2021 年以前的真实缺口由 WP-0059 补采并发布新版本，未补齐前相关 V2 和历史
  证据继续失败关闭。

### P1：交易时段与传输健康分离

- 连续竞价无更新、午间休市、收盘后、非交易日、进程断开和完成日落后分别建模；
- 十秒无 Tick 只在预期持续更新的交易阶段表示延迟，不能把最新盘后日线标为陈旧；
- 市场状态、最后完成日、`market_time` 和 `received_at` 保持不同字段和业务文案。

## 验收标准

### 行情与数据

Given 只有 L1 权限，When 启动行情适配器，Then L1 全推可用且 L2 明确显示不可用，
系统不生成伪 L2 数据。

Given 行情 RPC 断开，When 数据超过新鲜度阈值，Then 下游看到 Stale/Disconnected，
恢复后新会话身份和缺口范围可追溯。

Given 一个快照混合 Tushare 历史与 MiniQMT 实时数据，When 查看清单，Then 每个数据集
都有独立提供方、版本、可用时间、内容哈希和已知缺口。

Given 市场正在交易，When 前端消费当前会话投影，Then 同时看到最后完成日快照、实时
会话、`market_time`、`received_at`、新鲜度和缺口，且形成中的当日数据不会改写完成日
身份。

Given 一个日频粗筛批次已经冻结 20 只候选，When 请求分钟/Tick 验证数据，Then 请求在
读取任一日内值之前固定全部 20 只、截止时间、字段和窗口，并对每只返回完整、合法无
成交或明确失败证据；系统不会只保存验证通过者。

Given 相同冻结请求再次执行但提供方内容发生变化，When 发布研究数据，Then 旧版本保持
可重建，新内容使用不同身份并附差异，既有策略证据不被回写。

Given 收盘封存的日内数据存在无法解释的缺口，When 构建研究 `DataSnapshot`，Then
相关候选进入数据不足或整个请求失败关闭，当前会话投影不能作为补值来源。

Given 一个工作文件与已发布制品共享 inode，When 工作文件发生追加或替换，Then
完整性检查必须发现旧制品哈希/范围漂移、阻断正式消费，并要求发布新版本。

Given 用户遍历某证券上市以来历史，When 单次查询达到响应上限，Then API 返回稳定
游标或下一日期窗口，最终可以到达主表登记的上市日或最早可靠记录。

Given 最近完成日等于最近交易日且当前为收盘后，When 十秒没有 Tick，Then 状态为
“今日已收盘 · 日线数据最新”；只有传输进程断开时才显示“实时连接中断”。

### 账户与执行

Given 同时存在模拟盘和实盘，When 查询账户，Then 返回结果明确标记账户模式且不暴露
真实账户标识。

Given 没有本工作包级账户授权，When 应用准备调用账户查询，Then 失败关闭且不发出 RPC。

Given 同一异步委托回调重复或乱序到达，When 映射执行事件，Then 事件幂等、顺序可解释，
订单状态不回退。

Given 启动对账存在持仓或未完成委托差异，When 准备提交新订单，Then 新订单被阻断并显示
可行动的差异原因。

Given 只有本需求批准，When 尝试 Paper 或 Live 下单，Then 系统拒绝并要求对应受保护批准。

### 证据

- 行情和账户端口合同测试；
- RPC 录制 Fixture 的脱敏与许可证审查；
- 断线、重连、重复、乱序、陈旧和权限不足负例；
- Local Replay、Research Shadow 和 Paper 的 `OrderPlan` 语义一致、账本隔离且
  Research Shadow/Replay 都不能累计 Paper 成熟度的契约证据；
- Live 前的只读探针、启动对账、急停和首单检查单；
- 文档、日志和 Fixture 密钥扫描通过。

## 兼容与回退

- MiniQMT 不可用时，历史研究继续使用已发布的不可变数据快照。
- 实时功能进入 Disconnected/Stale，不自动切换到来源不明的“最新值”。
- Paper/Live 网关故障只影响执行适配器，不改变策略、组合或既有事件历史。
- 任一数据集只有在覆盖、时间语义和质量优于或补充现有来源时才纳入正式快照策略。
