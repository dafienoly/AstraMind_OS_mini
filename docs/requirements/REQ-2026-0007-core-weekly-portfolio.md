## 1. 单一目标与成功定义

本需求只建设 10 万元核心分仓的周度、A 股长仓因子研究与 MiniQMT Paper 候选。系统每天
形成可研究因子与诊断，在每周最后一个沪深共同交易日冻结 H20、H60 两条独立预测线，
再用固定各 50% 的虚拟预算生成一个允许现金、通常五只股票的组合。

首期的一个主目标是：在完整 A 股执行约束和 C2 成本压力下，提高核心组合绝对收益。
相对市场和相对申万一级行业只作两类诊断，不替代绝对收益目标。

成功不等于一次回测胜出。成功必须同时具备：

1. 可重建的点时数据、因子、模型、校准、组合和证据身份；
2. H20 与 H60 独立通过声明门槛，且组合策略通过更严格的联合门槛；
3. 合格候选可以独立运行 Research Shadow，用户再从中显式选择唯一
   `Core Paper Candidate`；
4. 至少形成可区分“历史冻结回放”“Research Shadow 前向研究”和“获准确授权后的
   Paper 券商事实”的证据；
5. 选择候选不自动连接 MiniQMT、创建 StandingMandate、提交 Paper 委托、进入 Live
   或使用真实资金。

## 4. 决策时钟、标签与证据周期

### 4.1 周度决策时钟

`T` 是该周最后一个上交所与深交所共同交易日。只有完整日度管线提交不可变
`DataSnapshot` 后，才可冻结 `FeatureSnapshot`、模型身份、校准器和预测。

- 名义信号冻结：T 日收盘后；
- 研究入场价：T+1 共同交易日的连续研究开盘价；
- H 日终点：T+H 共同交易日的连续研究收盘价；
- 标签：`r(i,T,H) = P_research_close(i,T+H) /
  P_research_open(i,T+1) - 1`；
- 主标签：当日 U0 内 `r(i,T,H)` 的截面百分位秩，平均秩处理并列；
- 相对市场诊断：`r(i,T,H) - r(U0_equal_weight,T,H)`；
- 相对行业诊断：`r(i,T,H) - r(SW_L1_equal_weight,T,H)`。

T 日截止后出现的公告、修订或行情只能进入 T+1 执行前预检，用于阻断或降低风险，
不得修改已冻结预测。错过 T+1 开盘窗口不追价、不补做该周期名义交易。

### 4.2 周期分工

| 周期 | 用途 | 可否训练模型 | 可否产生组合 | 可否晋级 |
| --- | --- | --- | --- | --- |
| D1/D3/D5 | 因子全周期诊断 | 否 | 否 | 否 |
| H20 | 独立生产预测、证据和候选 | 是 | 是 | 是 |
| H60 | 独立生产预测、证据和候选 | 是 | 是 | 是 |

D1/D3/D5 的结果不得参与 H20/H60 特征选择、超参数选择、候选替换或晋级判断。
D20/D60 的每日因子诊断可用于解释相应生产周期，但生产证据按周度决策截面计算。

所有百分位统一为 `(average_rank - 1) / (n - 1)`，升序排列且最大值为 1；`n<2`
时该截面无效。实现不得在不同步骤混用 `rank/n`、分位桶标签或随机打破并列。

标签成熟前不得进入训练。滚动切分在训练区间末端按最长 H60 删除尚未成熟标签；
不用对称 embargo，因为特征只向后看、训练只向前推进。任何实现若加入 embargo，
必须建立新证据身份，不能静默改变本口径。

## 5. U0、可交易性与容量

### 5.1 U0 身份

`U0-v1` 的基础成员是决策时点已上市的上交所主板、科创板、深交所主板和创业板 A 股。
北交所不进入首期；沪深 300、中证 500、中证 1000 等指数成分只作点时诊断，不改变
U0。

生产候选还必须同时满足：

1. 从上市日起已度过至少 252 个沪深共同交易日；不足者进入新股诊断池；
2. 决策时点不是已知 ST、`*ST`、退市整理或状态未知；
3. 最近 20 个共同交易日原始成交额中位数不少于 20,000,000 元；
4. 关键价格、风险状态和上市身份可点时重建。

临时停牌或没有成交不会从历史面板删除该证券：当日成交额按 0 计、因子按实际状态
标记；它不能新增风险，但已有持仓仍进入估值、风险和恢复路径。

### 5.2 容量公式

最近 20 日成交额中位数为：

`median_amount_20(i,T) = median(amount_raw(i,d), d ∈ last_20_common_sessions(T))`

停牌、无成交或缺少合法成交 Bar 的共同交易日使用 0；不足 20 个共同交易日直接
不合格。净额合并、100 股修复后的每个单边计划订单必须满足：

`abs(order_notional(i)) <= 0.001 * median_amount_20(i,T)`

T+1 按实际可执行价格再次检查；超限只能缩量到合法整数手或留现金，不拆单、不追价。

## 6. F0 原生 24 因子公式

所有价格 `P` 使用连续研究价；`amount`、`volume`、换手率和市值使用当时可见的原始
口径。财务流量使用点时正确 TTM，存量使用最新可用期末值。除表内说明外，`Avg`
表示期初期末平均，`Med20`/`Mean20` 使用最近 20 个共同交易日。

| 家族 | ID | 原始公式 | B0 方向 |
| --- | --- | --- | --- |
| 价值 | `EP_TTM` | 归母净利润 TTM / 总市值 | 正 |
| 价值 | `BP` | 归母权益 / 总市值 | 正 |
| 价值 | `SP_TTM` | 营业收入 TTM / 总市值 | 正 |
| 价值 | `DY_TTM` | 决策时点前 12 个月已公开且已具备实施依据的每股现金股利 / 决策时点股价 | 正 |
| 盈利 | `ROE_TTM` | 归母净利润 TTM / 平均归母权益 | 正 |
| 盈利 | `ROA_TTM` | 净利润 TTM / 平均总资产 | 正 |
| 盈利 | `OPERATING_MARGIN_TTM` | 营业利润 TTM / 营业收入 TTM | 正 |
| 质量 | `OCF_TO_NET_INCOME_TTM` | 经营现金流净额 TTM / 净利润 TTM | 正 |
| 质量 | `ACCRUALS_TO_ASSETS_TTM` | (净利润 TTM − 经营现金流净额 TTM) / 平均总资产 | 负 |
| 质量 | `DEBT_TO_ASSETS` | 总负债 / 总资产 | 负 |
| 成长 | `REVENUE_TTM_YOY` | 营业收入 TTM / 上年同期营业收入 TTM − 1 | 正 |
| 成长 | `NET_PROFIT_TTM_YOY` | 归母净利润 TTM / 上年同期归母净利润 TTM − 1 | 正 |
| 成长 | `OCF_TTM_YOY` | 经营现金流净额 TTM / 上年同期经营现金流净额 TTM − 1 | 正 |
| 动量 | `MOM_20_5` | `P_close(T−5) / P_close(T−20) − 1` | 正 |
| 动量 | `MOM_60_5` | `P_close(T−5) / P_close(T−60) − 1` | 正 |
| 动量 | `MOM_120_20` | `P_close(T−20) / P_close(T−120) − 1` | 正 |
| 动量 | `INDUSTRY_REL_MOM_60_5` | `MOM_60_5` − 同期点时申万一级等权收益 | 正 |
| 反转 | `REV_5` | `−(P_close(T) / P_close(T−5) − 1)` | 正 |
| 反转 | `RESIDUAL_REV_20` | 20 日个股简单收益对 U0 等权收益和点时申万一级等权收益 OLS 残差和的负值 | 正 |
| 低波 | `REALIZED_VOL_20` | `sqrt(252) * std(log(P_close(d)/P_close(d−1)))`，20 日 | 负 |
| 低波 | `DOWNSIDE_VOL_60` | `sqrt(252 * mean(min(r_d,0)^2))`，60 日 | 负 |
| 流动性 | `LOG_MEDIAN_AMOUNT_20` | `ln(1 + Med20(amount_cny))` | 正 |
| 流动性 | `TURNOVER_MEAN_20` | `Mean20(turnover_rate)` | 正 |
| 流动性 | `AMIHUD_20` | `ln(1 + 10^8 * Mean20(abs(r_d)/amount_cny_d))` | 负 |

共同规则：

- 分母为 0、符号导致增长比率失去经济含义或输入非法时标记 `missing`，不得加任意
  epsilon 制造数值；
- 成长比率要求当前与上年同期分母同号且上年同期绝对值大于 0，否则 `missing`；
- `RESIDUAL_REV_20` 至少需要 15 个共同有效观测；行业身份缺失则 `not_applicable`；
- Amihud 遇到无成交日不计算单日比值，整项由覆盖规则决定；容量判断仍把无成交额记 0；
- 规模 `log(float_market_cap)` 和点时申万行业是控制平面，不计入 F0 的 24 维。

### 6.1 财务点时构造

- 有准确公告时间的记录从该时间起可用；
- 只有公告日期的记录从下一沪深共同交易日收盘后可用；
- 修订只从修订实际可用时间起生效，不回写旧快照；
- 流量 TTM：`本年累计 + 上年全年 − 上年同期累计`；
- 资产负债表取最新已披露期末值；ROE/ROA 在期初期末均可用时使用平均值；
- 缺季度、不可比口径或不完整累计值失败关闭，不按月份机械年化。

银行、保险、券商保留在 U0。价格、动量、波动和流动性因子照常适用；普通企业财务
因子对这些行业标记 `not_applicable`，不强行套用。F0-FIN 另立需求。

### 6.2 B0 复合锚点

B0 先按表内方向统一正负，再对每个适用家族内的处理后因子等权平均，最后对适用家族
等权平均。普通企业最多八个家族，金融企业首期只使用动量、反转、低波、流动性四个
家族；缺失指示仍保留。B0 不学习权重。

永久锚点 `R0` 是 `F0-full × B0 × O0` 的 lineage。R0 与同一 B0 精确重复时只计算
一次，界面以“R0 / B0”同一候选展示。

## 7. 价格、行业和 Alpha101 语义

`data_semantics_version` 必须固定下列映射：

- OHLC 使用连续研究价格指数；
- VWAP = 原始成交额 / 原始成交量，再缩放到相同连续研究价格指数；
- 收益由连续研究收盘价计算；
- 成交量、成交额、换手率、流通/总市值使用原始点时值；
- 前复权、后复权兼容价只用于审计，不进入因子或执行；
- 原始价格用于成交、费用、整数手和容量。

Alpha101 的 `IndNeutralize` 严格映射：

| 论文层级 | A 股严格映射 |
| --- | --- |
| sector | 点时申万一级 |
| industry | 点时申万二级 |
| subindustry | 点时申万三级 |

缺少可信点时层级时，对应公式为 `not_applicable`；不得向上回退、使用当前行业或静默
近似。未来 A 股近似实现必须使用独立 `Alpha101-CN` 身份。

## 8. 缺失、外层处理与选择

### 8.1 三态可用性

每个因子值必须是：

- `observed`：按公式合法计算；
- `missing`：本应适用但输入缺失、非法或覆盖不足；
- `not_applicable`：公式对该证券/行业或所需行业层级不适用。

不得把任一状态写成 0。因子进入候选的覆盖门槛是：在其适用股票池中，至少 90% 的
训练日期达到 80% 的 `observed` 覆盖；未通过则整个因子在该折失败关闭。

模型视图按决策日先用点时申万一级行业中位数填补 `missing`，行业内至少需要 10 个
`observed`；否则使用当日 U0 中位数。`not_applicable` 保持独立指示，再用当日 U0
中位数提供数值占位。每个非 observed 状态生成独立指示列。任何包不得通过删除股票
获得更漂亮的覆盖。

### 8.2 统一外层处理

原始公式值永久保存。主处理按每个决策日、每个因子在 U0 截面执行：

1. 非有限值转为 `missing`；
2. `m = median(x)`，`s = 1.4826 * median(abs(x-m))`；
3. 缩尾到 `[m−5s, m+5s]`；
4. `z = (x−m)/s`。

当 `s=0` 时合法有限值统一输出 `z=0` 并记录 `zero_scale`，不得添加可调 epsilon。
原始值、缩尾值、z 值、填补来源和指示列都要可重建。

行业/规模中性化只作平行诊断：将主 z 值对截距、`log(float_market_cap)` 和点时申万
一级 one-hot 做截面 OLS，保存残差；样本数小于设计矩阵列数的 5 倍、矩阵不满秩或
控制缺失时诊断为不可用，不覆盖主特征。

### 8.3 `full` 与 `selected`

- `full` 永久保持规范全部公式和顺序；
- `selected` 只使用当时训练折内数据生成并冻结清单；
- 2023–2025 回放使用 2022-12-31 前已冻结清单；
- 联合包只允许 `selected`，不得构建 full 联合。

每个因子在打开开发证据前必须登记预期方向和经济机制；改变方向、机制或适用范围即
创建新的因子定义版本，不能根据开发期或历史冻结回放结果反向改写。

每个包、每个 H20/H60 独立选择：

1. 对每日截面 RankIC 先乘预登记方向，记均值为 `mu`；对中心化序列 `IC−mu` 使用
   20 交易日圆形移动区块、10,000 次重采样，单侧
   `p = (1 + count(centered_bootstrap_mean >= mu)) / 10001`；
2. 在同一包、同一周期内使用 Benjamini–Hochberg，FDR ≤ 10%；
3. 对通过项计算逐日截面 Spearman 相关的时间中位数；
4. `abs(median_corr) ≥ 0.85` 视为同簇，以完全链接避免链式误合并；
5. 簇内依次保留：预登记方向跨折一致、公式更简单、覆盖更高、换手更低、稳定性更高、
   注册 ID 字典序更前者。

重采样种子由因子定义版本、周期和训练折身份的 SHA-256 前 64 位无符号整数生成。
选择结果、被剔除原因和相关簇必须保存；H20-selected 与 H60-selected 允许不同，
不得为减少候选数强制取交集。

## 9. 训练、候选预算与组合阶梯

### 9.1 时间切分

- 主训练窗：截至每次训练日向后 5 年滚动；
- 扩展窗：从首个合格日期开始扩展，仅作诊断；
- 开发期：截至 2022-12-31；
- 历史候选冻结回放：2023-01-01～2025-12-31；
- Research Shadow 前向证据：准确候选登记后首个合法周度决策起的新到达数据，候选
  使用独立 100,000 元虚拟账本；历史本地回放不得追认；
- Paper 券商证据：显式选择 Core Paper Candidate 并取得准确 Paper 授权后的券商
  事实；Research Shadow 不得追认为 Paper；
- 推理：每周；
- 重训：每季度；
- 晋级：永远显式人工决定。

2023–2025 在需求批准前已客观存在，因此只称“候选冻结后的历史回放”，不得宣称真正
未见封存。当前季度模型不得回填为历史模型；历史表现属于各折真实模型产物。

### 9.2 模型

| 模型 | 定位 | 首期约束 |
| --- | --- | --- |
| B0 | F0 家族等权复合 | 无学习权重，永久 R0 |
| Ridge | 主比较 | 平方损失；9 个固定 alpha |
| LightGBM | 非线性挑战者 | 平方损失；每槽 8 个固定模板；一个主种子 |

Ridge 每个周期最多 10 个特征配置：六个单包
`F0/F1/F2 × full/selected`、三个 selected 两两联合，以及一个有条件 selected 三包
联合。只有至少一个两包联合在开发期 C2 总收益为正且相对更强单包年化提升大于 0，
三包联合才可进入；两包赢家按开发期证据选择，并以低换手打破并列。

LightGBM 每周期最多四个槽：最佳 F0、最佳 Alpha158、最佳 Alpha101、最佳已允许联合。
每槽最多八个固定模板；主种子用于选胜，额外两个种子只报告稳定性，不能换赢家。
LightGBM 还必须相对同配置 Ridge 的开发期 C2 年化增量 bootstrap 第 10 百分位大于 0。

Ridge alpha 固定为
`[1e-4, 1e-3, 1e-2, 1e-1, 1, 10, 100, 1000, 10000]`，包含截距，不惩罚截距。
Ridge 与 LightGBM 都预测主标签，并给每个训练日期相同总权重、日期内每只股票权重
`1/n_date`。

LightGBM 八个模板是
`max_depth ∈ {3,5} × min_data_in_leaf ∈ {50,200} × feature_fraction ∈ {0.7,1.0}`；
`num_leaves` 分别固定为 7/31，其他固定值为：L2 正则 1、L1 正则 0、
`learning_rate=0.03`、最多 500 棵树、验证集 50 轮早停、`bagging_fraction=0.8`、
`bagging_freq=1`。主种子为 `20260729`，诊断种子为 `20260730/20260731`。库版本和
确定性参数属于模型身份；若某版本不能保证确定性则失败关闭。

开发期先过滤资格，再最大化 C2 年化净收益增量的 bootstrap 第 10 百分位；并列依次
选择低换手、少特征、注册 ID 字典序更前者。2023–2025 每个周期只打开 R0、最多一个
Ridge 决赛者、最多一个 LightGBM 决赛者；名单在回放前冻结，失败后不得用亚军替补。

### 9.3 单包到联合

顺序固定为：单包 → selected 两包联合 → 有条件 selected 三包联合。首期只做特征级
拼接。跨包逐日截面 Spearman 时间中位数绝对值达到 0.85 时按第 8.3 节同样规则去重，
但不修改各包 full 身份。预测级融合和动态权重后置。

## 10. 预测转绝对收益校准

校准器按 `Strategy Lineage × H20/H60` 独立建立：

1. 只使用滚动样本外预测；
2. 每个决策日将预测转为 U0 截面百分位，平均秩处理并列；
3. 只取注册周度决策截面，按百分位分 10 桶；
4. 每个日期总权重相等，日期内每只股票权重为 `1/n_date`；
5. 对各桶实际绝对 H 日收益均值使用 PAVA 做非递减 isotonic 拟合；
6. 预测映射到所在桶，边界外只截到边界桶，不线性外推。

主窗使用最近 5 年成熟样本，至少 156 个有效周度样本截面。最高桶拟合收益必须严格
高于十桶拟合收益中位数，且最高分受约束篮子在 C2 下预期净收益为正，否则校准无效。

校准器在下一计划季度重训日到期。失效、陈旧或方向检查失败时不得新增风险，没有
宽限期；恢复后仍按第 13 节两周确认。首期禁止另建行业专属或市场状态专属校准器，
也不得用 X0 上下文切换校准曲线。

## 11. 成本与可执行收益

### 11.1 费用公式

每笔实际整数手订单独立计算，金额使用 `Decimal`，每个费用分量按人民币分四舍五入：

`commission = max(5.00, notional * commission_rate)`，订单金额大于 0 时适用。

- 股票全佣费率：0.000086；
- ETF 全佣费率：0.00005；
- 股票与 ETF 都保留每笔最低 5 元；
- 全佣已包含经手、证管、过户等券商口径项目，不得再次叠加；
- 股票卖出印花税按交易日有效法定费率另计；
- ETF 不收股票印花税；
- 历史回放按交易日选择版本化法定费率，旧证据不因未来费率变化而改写。

“四舍五入”固定为 `ROUND_HALF_UP`，每个费用分量先到人民币分，再求订单总费用。

滑点压力按每边 5/10/20/50 bp 分别形成 C0/C1/C2/C3：

`slippage_cost = notional * bps / 10,000`

证据比较必须使用同一费用版本。C2 是所有晋级硬门的主成本情景，其他情景用于诊断。

### 11.2 边际成本

- 新买入：计完整预期往返费用和 C2 滑点；
- 继续持有：不重复计已发生买入成本；
- 替换：比较“继续持有旧股”和“卖旧买新”的增量路径；
- 最低 5 元按最终实际订单逐笔计算，不能按组合名义比例摊薄；
- H20/H60 对同一证券的买卖先净额合并，再做整数手、费用和容量计算。

## 12. O0：单一核心组合

### 12.1 固定预算和选择

H20、H60 各占 50,000 元固定虚拟预算。某周期失效时其预算留现金，不向另一周期
重分配。

权重恒等式固定为：

- `sum_i(w20_i) <= 0.5`；
- `sum_i(w60_i) <= 0.5`；
- `w_final_i = w20_i + w60_i`；
- `cash_weight = 1 - sum_i(w_final_i)`。

对每个周期，将校准后的净预期收益转成可比较五日分数：

`score_5d = exp((5/H) * ln(1 + expected_net_return_H)) - 1`

`expected_net_return_H <= -1` 为非法并阻断。联合 O0 先按
`0.5 * score_5d_H20 + 0.5 * score_5d_H60` 形成最终排名，再从可执行候选中最多选五
只。每个周期只向其自身正分且进入最终名单的股票等额分配该周期预算；不支持的贡献
保持现金。

H20/H60 原始预测、百分位、校准后绝对收益、预计成本和五日分数必须分别保存。上述
加权只属于 O0 的确定性组合转换，不得标为学习式预测融合。

### 12.2 约束与修复

- 最终持仓 0～5 只，目标为 5 只；
- 单股最终权重 ≤ 25%；
- 点时申万一级最终权重 ≤ 40%，且最多两只；
- 100 股整数手；
- 精确费用现金预留；
- 最终净额订单全部通过 0.1% 容量门；
- 任何不可行部分留现金，不归一化到剩余股票。

约束修复只允许减少目标股数、减少股数或增加现金。每次修复后重新计算唯一持仓数、
行业、费用、换手、容量和风险，直到合法或明确无解。连续权重指标不得冒充整数手后的
最终组合。

### 12.3 Top5/Top10 滞回

- 新增风险要求候选进入最终 Top5，且受约束篮子 C2 预期净收益大于 0；
- 已持股票在 Top10 内继续持有，不做机械漂移再平衡；
- 只有旧股跌出 Top10、替代者在 Top5 且替换的 C2 边际收益大于 0 才允许主动替换；
- 每周最多一次自愿替换，首次建仓豁免；
- 风险退出、不可交易恢复和强制处置不占自愿替换额度；
- 不设机械最短持有期。

## 13. 信号有效性状态机

每个周期独立维护：

“有效强信号”要求数据、模型、校准和方向检查健康，且受约束篮子 C2 预期净收益大于
0；“有效弱信号”表示系统健康但该绝对收益门失败。数据、模型、校准、方向检查或管线
本身失败属于 `SYSTEM_INVALID`，不能伪装成弱信号。

| 状态 | 进入条件 | 动作 |
| --- | --- | --- |
| `ACTIVE` | 已确认有效 | 可按 O0 新增/调整风险 |
| `WEAK_PENDING` | 第一个有效弱信号周 | 不新增风险，已有贡献不主动退出 |
| `RETREATING` | 连续第二个有效弱信号周 | 最多按共享额度每周退出一个自愿仓位 |
| `RECOVERY_PENDING` | 退让后第一个有效恢复周 | 停止退让但不新增风险 |
| `SYSTEM_INVALID` | 数据、模型、校准或管线系统性失效 | 冻结，不更新强弱计数 |

第二个连续有效恢复周回到 `ACTIVE`。系统失效不能伪造卖出信号；独立账户/组合风险仍
可减少风险。若只有一个周期失效，同一股票只移除该周期贡献，另一周期贡献继续有效。

## 14. 策略身份、参照与人工决定

### 14.1 四层身份

- `Strategy Lineage`：稳定的因子语义、选择清单和训练配方；
- `StrategyVersion`：lineage 在某次季度训练产生的准确模型产物；
- `Lineage Evidence Version`：由各历史折真实模型产物组成的证据版本；
- `CorePolicyVersion`：绑定准确 H20、H60 版本、固定预算、O0、成本和约束的组合策略。

当前模型不能回填历史。季度重训创建新的 `StrategyVersion`；只有因子、选择清单、
超参数空间或训练配方变化才创建新 lineage。

### 14.2 三级参照

- R0 永久锚点：`F0-full × B0 × O0`；
- R1 初始主比较：`F0-selected × Ridge × O0`；
- incumbent：当前在位版本；
- direct parent：本候选增加复杂度前的直接父级。

R0 对首次选择非 R0 lineage 是硬参照，自身豁免；incumbent 只在替换时是硬参照；
direct parent 只在增加复杂度时是硬参照。精确重复只检验一次。稳定运行的联合
CorePolicy 只比较 incumbent；模型父级比较留在各 H20/H60 层。

### 14.3 三类人工决定

- `Promotion`：新 lineage 首次取得生产资格，必须通过完整门；
- `Renewal`：同 lineage 季度新准确版本，不改变特征/超参数配方；
- `Fallback`：只能回到兼容 R0 或 prior champion，必须记录原因。

Renewal 要求 lineage 配方 C2 总收益为正，且
`P(ΔCAGR >= -1 percentage point) >= 90%`，并通过组合回撤/Calmar、准确模型产物和
校准验收。Fallback 只检查自身绝对门，不要求相对门；失败实验不能强迫回退任意版本。

每季度 H20/H60 独立通过或失败，随后只生成一个确定的 CorePolicy 更新：新版本通过则
使用新版本；新版本失败但旧版本仍有效则保留旧版本；两者都无效则该周期预算现金。
用户一次原子确认该 CorePolicy，不做跨周期版本笛卡尔选择。

所有合格的 R0/B0、Ridge、LightGBM 决赛者都可人工选择；“基线/挑战者”标签不是权限。
无总分自动排序、无自动晋级。

Promotion 记录必须同时绑定用户选中的准确 `StrategyVersion`、对应
`Lineage Evidence Version`、模型产物验收、校准器身份和决定时适用的参照集合；任一
身份缺失都不能创建生产资格。

## 15. 统计公式与晋级门

### 15.1 周度 RankIC

每个周度决策日，在当日点时 U0 上计算预测与成熟主标签的 Spearman RankIC；并列使用
平均秩，不因未来无收益而删除当日股票。标签覆盖必须不少于当日 U0 的 95%，否则该周
无效并记录原因。

每个 H20/H60 的历史冻结回放硬门：

- 平均周度 RankIC ≥ 0.02；
- RankIC 为正的有效周占比 ≥ 55%。

Q5−Q1、五分位单调性、ICIR、指数/行业/市场状态拆解只作诊断。

### 15.2 配对圆形移动区块 bootstrap

候选和每个有效参照使用完全相同的周末、C2 净收益和共同交易日。系统性无效周可按同一
排除账本从两边同时排除；候选特有缺失不得 pairwise 删除，直接使比较失败。有效覆盖
少于计划周的 95% 时证据无效。

- H20 区块长度：4 周；
- H60 和联合 CorePolicy：12 周；
- 重采样次数：10,000；
- 区块从圆形序列任意位置开始并允许绕回；
- 种子：候选证据 ID、参照证据 ID、周期和成本版本拼接后 SHA-256 前 64 位无符号整数。

每次重采样分别复利候选和参照路径。若任一单期收益 ≤ −1，证据失败关闭。

`CAGR = (ending_NAV / starting_NAV)^(252 / N_common_sessions) - 1`

`ΔCAGR_pp = 100 * (CAGR_candidate - CAGR_reference)`

“增量为正概率”是 10,000 个重采样中 `ΔCAGR_pp > 0` 的比例。

### 15.3 分层硬门

H20/H60 新 lineage：

1. C2 整段净收益大于 0；
2. RankIC 两项门槛通过；
3. 对每个当期有效硬参照，`P(ΔCAGR > 0) >= 90%`；
4. 对每个当期有效硬参照，原始样本 `ΔCAGR_pp >= 2`。

Horizon 层不再叠加年度、回撤、Calmar 或换手硬门，避免重复门槛。

联合 `CorePolicyVersion`：

1. C2 整段净收益大于 0；
2. 三个完整日历年中至少两年 C2 净收益大于 0；
3. 对每个当期有效硬参照，`P(ΔCAGR > 0) >= 90%` 且
   `ΔCAGR_pp >= 2`；
4. 对每个参照，三个完整日历年中至少两年相对收益大于 0；
5. C2 日度可执行 NAV 最大回撤小于 12%，Calmar ≥ 0.5；
6. 年化单边换手 ≤ 500%，全部最终订单通过容量门。

单一年份相对落后超过 5 个百分点只标黄色诊断，不是额外硬门。

### 15.4 NAV、风险与换手

日度可执行 NAV 使用原始可成交价格、现金、费用、公司行动和真实整数手持仓。最大回撤：

`MDD = min_t(NAV_t / max_{s<=t}(NAV_s) - 1)`

`Calmar = CAGR / abs(MDD)`；`MDD=0` 且 CAGR>0 时记为 `+∞`，两者都为 0 时为 0。
Sharpe、Sortino、相对最大回撤和 CVaR 只作诊断。

单边换手：

`turnover_t = 0.5 * sum_{i in stocks+cash} abs(w_after_i - w_before_i)`

被动价格漂移不计交易换手；风险退出计入并单独标注；初次建仓单独展示。年化换手等于
有效区间单边换手和乘以 `252 / N_common_sessions`。同时报告周度中位数、P95 和逐年值。

## 16. 组合风险动作

核心分仓与账户层沿用已批准回撤规则，较严格者优先：

- 8%：禁止扩大总风险；
- 10%：禁止任何买入或加仓；
- 12%：禁止买入，并只生成减仓/清仓提案，不自动卖出。

这些动作可覆盖信号状态机和 O0，但不能反向改写预测或历史证据。

## 17. Research Shadow、Paper 成熟度与 UI 行为

所有合格决赛者可按 REQ-2026-0014 运行独立 Research Shadow。Research Shadow
有效周要求数据、模型、校准和 O0 健康，并保留合法 no-action、现金、阻断和失败事实；
它可以支持显式 Promotion/Renewal/Fallback，但不证明券商成交或账户恢复。

人工选择只创建一个 `Core Paper Candidate`；取得独立 StandingMandate 和 MiniQMT
写入授权后，Paper 成熟度只按券商确认的有效周计算：

- 少于 13 个有效周：证据不足；
- 13～25 个有效周：早期观察；
- 至少 26 个有效周且包含两个不重叠的成熟 H60 结果：运营成熟。

有效周要求数据、模型、校准、O0、启动对账和 Paper 收敛均完成；合法 no-action、
现金和风险阻断仍是有效周。系统失效、MiniQMT 断开、账户模式未知、对账未收敛或
回调未知的周无效。联合 CorePolicy 的有效周要求两个周期都形成健康判断。
Local Replay 和 Research Shadow 周都不得计入 Paper 成熟度。没有固定等待期，也不
自动进入 Live。

未来 UI-PROP-0005 v0.2 至少必须：

- 在 H20/H60 分区展示准确 R0/B0、Ridge、LightGBM 决赛者；
- 允许选择所有 eligible 候选，禁用 blocked 候选并显示原因；
- 默认 incumbent，显示 lineage 当前版、最新版和历史版本；
- 每个 lineage 最多一个待 Renewal，不允许复活被绕过的旧未晋级版本；
- 预览唯一 CorePolicy、现金和 H20/H60 贡献；
- 分栏展示历史、Research Shadow 和 Paper 证据，不把虚拟账本显示为券商账户；
- 用一个明确确认动作记录 Promotion/Renewal/Fallback，不使用多层模态审批。

这只是行为要求，不构成 v0.2 视觉批准或 UI 实施授权。
