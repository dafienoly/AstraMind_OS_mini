# REQ-2026-0009：本地日常运行与恢复

- 需求版本：1.0.0
- 状态：草案，未批准实施
- 来源：2026-07-27 用户授权 WP-0007 对 REQ-2026-0001 进行规划收尾
- 目标阶段：阶段 2、4、7
- 实现状态：未开始；现有命令和 SQLite/WAL 只是开发及持久化基线
- UI：UI-PROP-0008 v0.1 待用户批准
- 追踪：见[需求索引唯一追踪表](./README.md#唯一追踪表)

## 目标

让单用户本地系统可以按日运行、发现陈旧或失败状态、从中断恢复并重建关键产物，同时
保持操作简单，不引入机构式发布和审批系统。

## 范围内

- 数据更新、快照发布、研究、Shadow 和后续模型作业的幂等调度；
- 不可变输入、幂等键、租约、心跳、有界重试、进度和失败原因；
- 进程重启、数据中断、提供方限流和磁盘故障后的安全恢复；
- 快照、SQLite、配置、模型及未来授权记录的备份和恢复演练；
- 结构化脱敏日志、健康、新鲜度和紧凑异常视图；
- 日更、查询、局部回测和预测性能基线；
- 本地操作、事故处理和数据重建指南。

## 范围外

- 多用户、远程托管或企业调度平台；
- 第二套数据真相或第二个执行引擎；
- 自动越过失败关闭状态；
- 未批准的 MiniQMT 账户或交易连接；
- UI-PROP-0008 获批前实现对应业务页面。

## 功能要求

1. 长历史重建和模型训练不得隐藏在 API 请求内。
2. 每个作业必须固定输入身份并支持幂等重试。
3. 未完成发布不得更新当前快照指针。
4. 陈旧、断开、阻断和错误必须可区分，并给出恢复动作。
5. 日志和健康接口不得包含 Token、账户标识、真实行情值或订单载荷。
6. 恢复演练必须证明关键投影可由不可变产物或事件重建。

## 验收标准

Given 作业在发布前中断，When 使用相同幂等键恢复，Then 不产生冲突版本且当前指针仍
指向最后一个完整版本。

Given 提供方限流或断开，When 重试预算耗尽，Then 作业进入可见失败状态并保留安全恢复
入口，不循环无限重试。

Given SQLite 投影丢失但事件和备份可用，When 执行恢复演练，Then 重建结果与恢复前身份
一致。

Given 查看日志、健康页和错误摘要，When 执行密钥扫描，Then 不包含 Token、账户标识或
真实订单内容。

## 待批准事项

- 日度作业时间窗及资源预算；
- 备份位置、保留周期和恢复点目标；
- UI-PROP-0008 的准确批准版本。
