## 目标

让单用户本地系统可以按日运行、发现陈旧或失败状态、从中断恢复并重建关键产物，同时
保持操作简单，不引入机构式发布和审批系统。

## 范围内

- 数据更新、快照发布、研究、Shadow 和后续模型作业的幂等调度；
- 不可变输入、幂等键、租约、心跳、有界重试、进度和失败原因；
- 进程重启、数据中断、提供方限流和磁盘故障后的安全恢复；
- 快照、SQLite、配置、模型及未来授权记录的备份和恢复演练；
- 结构化脱敏日志、健康、新鲜度和紧凑异常视图；
- 日更、查询、局部回测和预测性能基线；
- 本地操作、事故处理和数据重建指南。

## 范围外

- 多用户、远程托管或企业调度平台；
- 第二套数据真相或第二个执行引擎；
- 自动越过失败关闭状态；
- 未批准的 MiniQMT 账户或交易连接；
- UI-PROP-0008 获批前实现对应业务页面。

## 功能要求

1. 长历史重建和模型训练不得隐藏在 API 请求内。
2. 每个作业必须固定输入身份并支持幂等重试。
3. 未完成发布不得更新当前快照指针。
4. 陈旧、断开、阻断和错误必须可区分，并给出恢复动作。
5. 日志和健康接口不得包含 Token、账户标识、真实行情值或订单载荷。
6. 恢复演练必须证明关键投影可由不可变产物或事件重建。

## 已批准运行基线

1. 时区固定为 `Asia/Shanghai`；交易日以版本化交易日历和提供方完成状态共同判断。
2. 盘后增量数据、快照和决策流水线安排在 16:30 后；只有提供方确认最近完成交易日且
   所需数据集完整时才能推进目标与计划。
   龙虎榜/席位存在保守的 20:05 完成门；16:30 可以启动并核验其他数据，但事件尚未
   到窗时保持 `waiting_provider`，不得提交缺少目标日事件的生产快照。
3. 次交易日 08:30～09:20 用于恢复、行情握手和未来 Paper 启动对账；失败时当天券商
   动作保持阻断。
4. 长历史回填、完整封存回放和模型训练继续使用显式长任务，不进入日度关键路径。
5. 日度增量流水线超过 30 分钟进入 `stale` 或 `blocked` 并提示恢复，不以无限重试
   掩盖问题。
6. 备份目录由 `ASTRAMIND_BACKUP_DIR` 指向仓库和 `var/` 之外的位置；未配置或验证
   失败时，研究和 Shadow 可继续，但 Paper 写入保持阻断。
7. 每次追加式迁移前、首个券商写入前和每个完成交易日结束后建立备份；保留最近 30 个
   日度恢复点和 12 个自然月月末恢复点。
8. 不可变执行事件以券商重查和事件重放实现 RPO 0；本地投影允许重建，不把投影文件
   当作唯一事实。恢复目标为 30 分钟内回到可判断的健康或明确阻断状态。
9. UI-PROP-0008 未批准不阻塞后端和命令行实现；对应页面继续禁止实施。
10. 每个完成交易日的统一数据提交必须同时刷新证券主表、历史名称/ST 区间、公司行动、
    SW2021 行业分类注册表和行业成员关系；不得把上一快照中的身份数据静默沿用为当日已
    核验结果。
11. 证券主表、行业分类和成员关系采用当日完整提供方视图对账；名称/ST 与公司行动按
    实际公告/可用时间合并。任一关键引用数据请求失败、达到提供方上限、身份冲突或点时
    语义不明确时，保留上一完整快照并进入 `waiting_provider`、`blocked` 或
    `recovery_required`。

## 验收标准

Given 作业在发布前中断，When 使用相同幂等键恢复，Then 不产生冲突版本且当前指针仍
指向最后一个完整版本。

Given 提供方限流或断开，When 重试预算耗尽，Then 作业进入可见失败状态并保留安全恢复
入口，不循环无限重试。

Given SQLite 投影丢失但事件和备份可用，When 执行恢复演练，Then 重建结果与恢复前身份
一致。

Given 查看日志、健康页和错误摘要，When 执行密钥扫描，Then 不包含 Token、账户标识或
真实订单内容。

## WP-0015 实施结果

- 16:30～17:00 盘后与次交易日 08:30～09:20 盘前窗口已形成确定性决策；
- 提供方未完成、日度预算超时、备份未就绪和恢复失败分别输出明确阻断；
- SQLite 使用在线 Backup API 形成一致性副本，当前数据指针以相对路径和哈希保存；
- 备份清单不包含绝对路径、Token、账户标识或订单载荷；
- 隔离恢复核对文件哈希、SQLite 完整性和 Shadow 事件计数，不覆盖当前 `var/`；
- WP-0023A 已在私有 `.env.local` 配置真实仓库外目录并完成部署验收；
- 最新恢复点验证22个文件、4个 SQLite 和4条 Shadow 事件，状态为
  `paper_recovery_ready=true`，但不推导券商授权。
