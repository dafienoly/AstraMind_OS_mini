# ADR-0009：规范数据集路由与整批回退

Data 上下文以规范数据集请求选择提供方，不允许应用服务直接依赖 Tushare 接口名或
MiniQMT SDK 类型。每次管线运行开始时冻结版本化 `DatasetSourceRoute`。默认同一
数据集版本只有一个实际提供方；经用户明确批准的日期切源可以在一个版本中包含多个
不重叠的提供方时期，但必须同时写入路由 `provider_lineage`、清单
`provider_lineage` 和逐行来源。

主源超时、返回空数据、缺关键字段、主键重复或覆盖校验失败时，原始失败响应仍只追加
保存，但部分规范化结果全部丢弃，再由同一提供方时期允许的下一来源完整重取该数据集。
禁止逐行补缺和静默择值。原始记录、观察、`DatasetManifest`、`DataSnapshot` 和选源
证据都记录实际来源。同一交易日不得混用提供方，跨越切源日的单个采集请求必须拆分。

MiniQMT 原则上只有在完整生产范围内通过点时语义、覆盖、一致性和性能门禁后才能
成为主源；门禁要求端到端 P95 不高于 Tushare 的 50%，吞吐不少于两倍。用户可以因
明确的成本、可用性或供应商依赖取舍批准例外，但必须记录未通过项、基准报告、例外
原因和完整回退源。例外不允许降低整批回退、来源标记或不可变单源版本要求。

2026-07-29 用户基于 MiniQMT 免费且差距可接受，批准 `daily_market` 和
`broad_index_daily` 从当日开始使用 MiniQMT。2026-07-28 及以前已发布的 Tushare
历史保持不变；2026-07-29 及以后只接受 MiniQMT，不要求重抓 MiniQMT 全历史，也不
允许切源日后回退到 Tushare。生产报告
